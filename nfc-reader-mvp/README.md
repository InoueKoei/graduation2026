# 「な」しかないカルタ（NFCリーダー運用）

全部『な』の一文字で書体だけが違う札（NFCタグ）から、**お題の書体**を探してスキャンするタイムアタック。ふつうの人が書体をどれくらい見分けられるかを測るキット。

- iPhone を NFCリーダーとして運用（Apple Developer Program も自作アプリも不要／純正「ショートカット」＋ローカルWebサーバー）。
- **全8問**。お題（書体名）が1問ずつ出て、正解の札をスキャンすると次へ。**クリアまでのタイムを計測**。
- 画面は sumi design system ベースのモノクロUI。

## ゲームの操作（表示画面 `/`）

- **モードを選ぶ**（待機／終了画面で選択）：
  - **ヒントあり**：お題の書体で描いた大きな「な」を画面に表示（形を見比べて探せる）。
  - **ヒントなし**：書体名だけ（名前から書体を思い出して挑戦）。
- **スタート**：計測開始、1問目のお題（書体名）が即表示される。
- 札をスキャン → お題と一致で **○・次の問題へ**／違う札は **×・お手つき（振動）** でその問題に留まる。

> **読み上げ（詠み手）機能はオフ**にしてあります。ロジックは `public/readaloud.js` に退避（display.html から読み込んでいないので動きません）。「詠みます。→な→(0.5秒)→書体名」の読み上げ＋同期表示を戻したいときは、そのファイル冒頭の手順で再有効化できます。
- 8問そろえると自動で**終了＝クリアタイム表示**。途中でやめるなら **終了**。
- 出題数は `server.js` の `QUESTION_COUNT`（既定 8）。お題は `cards.json` の札からランダムに8問。

### 書体（ヒント表示）の設定

ヒントありの「な」は、`cards.json` 各札の **`font`（CSSの `font-family` 英語名）** で描画します。
その書体が表示端末（大画面を開く Mac 等）に入っている／Webフォント読込済みなら、その書体で出ます。空なら既定フォント。

```json
{ "id": "15", "title": "ヒラギノ角ゴシック", "font": "Hiragino Kaku Gothic ProN" }
```

> Webフォントを使う場合は `public/display.html` の `<head>` に `@font-face`／`<link>` を足し、`font` にそのファミリー名を入れてください。

## 全体の流れ（お題＝書体名との一致で動的判定）

```
表示画面で「スタート」→ お題（書体名）が1問ずつ出る
   ▼
NFCタグ (中身: http://192.168.10.130:3000/scan?card=01)
   │  札ごとに card= の値を番号にする (01 / 02 / 03 … = cards.json の id)
   ▼
iPhone「ショートカット」オートメーション「NFCを検出したら → URLを取得/開く」
   ▼
サーバー (server.js) が「スキャンした札 === いまのお題」を判定
   │  ★ 正解/不正解は cards.json に固定しない。お題で動的に決まる。
   │    正解で次の問題へ、全8問そろえるまでのタイムを計測。
   ▼
・iPhoneのSafariに結果がそのまま出る（1台で完結）
・Mac/iPadで http://192.168.10.130:3000/ を開いておくと大画面にリアルタイム表示（展示向き）
・不正解のときだけ手元が振動（後述のショートカット）
```

> Mac のIPは Wi-Fi/DHCP で変わります。**現在の接続URLは表示画面（`/`）の下部と、`node server.js` 起動時のターミナルに自動表示**されるので、そこを見てタグ/ショートカットのURLを合わせてください（`ipconfig getifaddr en0` でも確認可）。毎回変わるのが面倒ならルーターで Mac に固定IP（DHCP予約）を。

## 1. サーバーを起動

```bash
cd "nfc-reader-mvp"
node server.js
```

起動すると、タグに書き込むべきURLがターミナルに表示されます。

## 2. まずタグなしで動作確認

ブラウザで `http://localhost:3000/` を開く。上部にタイマーと**スタート**、下部にテスト用の札チップが並びます。

1. 「**スタート**」→ お題（書体名）が1問目として出る。太字のチップ＝いまのお題。
2. 下部の**チップ（札）**を押すとスキャンをシミュレートできる。
   - お題と**一致** → ○・次の問題へ（タイマー継続）
   - **違う札** → ×・お手つき（実機なら振動）。その問題に留まる。
3. 8問そろえると自動で終了し、**クリアタイム**が出る。

これで「お題の書体を探して当てる → 全8問のタイム計測」までのサーバー挙動が確認できます。

## 3. NFCタグに書き込む（実機検証）

用意するもの：書き込み可能なNFCタグ（NTAG213等、数十円）＋書き込みアプリ「**NFC Tools**」（無料）。

1. NFC Tools →「書き込み」→「レコードを追加」→「URL / URI」
2. 1枚目に `http://192.168.10.130:3000/scan?card=01`
3. 2枚目に `http://192.168.10.130:3000/scan?card=02`（card= を変えるだけ）
4. 3枚目に `…?card=03` …と、札の番号ごとに値を変える（cards.json の id と一致させる）

## 4. iPhone「ショートカット」でオートメーション

Safari を開くかどうかは**サーバーではなくショートカット側のアクション**で決まります。

| アクション | iPhoneの挙動 | 用途 |
|---|---|---|
| **URLを開く**（Open URL） | Safari が開いて結果ページが出る | 1台で結果を見せたいとき |
| **URLの内容を取得**（Get Contents of URL） | **画面は開かない。**裏でリクエストだけ飛ぶ | 大画面に出す・スキャンだけ通知したいとき（推奨） |

### 推奨：Safariを開かず、スキャンだけ通知する

1. ショートカットアプリ →「オートメーション」タブ →「＋」→「NFC」
2. 「スキャン」でタグを1枚読ませて登録 → 名前を付ける
3. アクション「**URLの内容を取得**」を追加し、そのタグのURL（末尾に `&format=json` を付ける：`http://192.168.10.130:3000/scan?card=01&format=json`）を入力
4. 「実行の前に尋ねる」をオフにすると即実行（※iOSのバージョンにより確認が挟まることあり）
5. タグごとに1オートメーションずつ作る

これで iPhone は何も画面を開かず、スキャンした事実だけがサーバーに届き、`/` を開いた Mac/iPad の大画面がリアルタイムに切り替わります。

### （任意）iPhone側にも軽く反応がほしい場合

Safari を開かずに、手元で反応だけ返せます。手順3の後にアクションを足す：

- **通知を表示**：`取得したコンテンツ` を辞書として扱い、`message` の値を通知本文に出す（○×つきの結果が手元にも出る）
- **デバイスを振動させる** / **サウンドを再生**：正誤に関係なく「読めた」合図だけほしいとき

### （任意）間違いのときだけ振動させる ← 実機で動作確認済みの手順

`&format=haptic` を付けると、サーバーは `vibrate` か `none` の**文字だけ**を返します。これをテキストとして比較して分岐します。

**動くレシピ（この順番・この設定でOK）**

1. 「**URLの内容を取得**」→ URL: `http://192.168.10.130:3000/scan?card=02&format=haptic`
2. 「**入力からテキストを取得**」→ 入力＝手順1の「URLの内容」
   （これで確実にプレーンテキストになる。※後述の落とし穴A回避）
3. 「**If（もし）**」→ 「**テキスト**」が **`vibrate`** を **含む** 場合
4. Ifの中（「その他の場合」ではない）に「**デバイスを振動させる**」
5. 「**If文の終了**」

これで正解の札（`none`）は無反応、間違い・未登録タグ（`vibrate`）だけ手元が振動します。
振動する/しないは「お題と一致したか」で毎回決まります（お題が変われば同じ札でも変わる）。

> **ハマりどころ（実際にハマった3点）**
> - **落とし穴A：URLに `&format=haptic`（辞書なら `&format=json`）を付け忘れる** → サーバーがHTMLを返し、「リッチテキストを辞書に変換できませんでした」エラー。
> - **落とし穴B：Ifで参照する対象を「ファイルパス」にしてしまう** → 中身ではなくファイルの保存パスと比較してしまい、絶対に一致しない。→ 手順2の「テキストを取得」を挟めば回避。
> - **落とし穴C：条件の値に引用符を入れてしまう**（`"vibrate"` と入力）→ 探す文字が `"vibrate"`（クォート込み9文字）になり、返り値 `vibrate`（7文字）と一致しない。**入力欄に打つのは `vibrate` の文字だけ**（クォートは文字列の"囲い"であって中身ではない）。
> - **補足**：ショートカット下部に出る値は「振動した証拠」ではなく「最後に生成された値（取得テキスト）」。Ifがスキップされると、その手前のテキストがそのまま最後に見える。

> 逆に「Safariに結果ページを出したい」ときは、手順3を「**URLを開く**」にし、`&format=json` は付けません。

## 5. 札を増やす・お題を出す

**正誤は `cards.json` では決めません**（お題との一致で動的に決まる）。`cards.json` は**札の一覧だけ**。札を足すには `{ id, title }` を追加するだけ（サーバー再起動不要）。`id` がタグの `card=` の値、`title` が札の文字。

```json
{ "cards": [ { "id": "01", "title": "UD新ゴ" }, { "id": "02", "title": "中ゴシックBBB" } ] }
```

お題の切り替えは表示画面のボタン、または URL で：
- `/prompt?card=02` … 指定の札をお題にする
- `/prompt?random=1` … ランダムに次のお題へ

## エンドポイント

| URL | 役割 |
|---|---|
| `/scan?card=01` | タグが叩く。お題と一致するか判定して結果ページ(HTML)を返す |
| `/scan?card=01&format=json` | 同上だがJSONを返す（辞書として扱う用） |
| `/scan?card=01&format=haptic` | `vibrate`（不正解）/ `none`（正解）の文字だけ返す（振動判定用） |
| `/game?action=start&mode=hint\|nohint` / `/game?action=end` | ゲーム開始（モード指定）/ 終了 |
| `/prompt?card=03` / `/prompt?random=1` | ゲーム外でお題を手動切替（確認用） |
| `/` | 大画面の表示画面（タイマー＋スタート/終了＋SSEリアルタイム） |
| `/api/state` | 現在のゲーム状態・お題・履歴・札一覧(JSON) |

## 制約・注意（検証で分かる前提）

- **同一Wi-Fi・同一サブネット必須**：iPhone と Mac が同じネットワークにいる必要があります（`http` のLAN内通信）。繋がらないときの定番原因：
  - **IPが変わった**：URLを現在のIPに更新（画面下部/起動ログ参照）。
  - **別サブネットにいる**：スマホの IP（設定→Wi-Fi→ⓘ）が Mac と同じ `192.168.x.y` 帯か確認。別帯（別SSID・別バンド・ルーター2段/ダブルNAT）だと届かない。
  - **ルーターのプライバシーセパレーター（AP隔離）** が有効：端末間通信を遮断するのでオフに。
  - macOS ファイアウォールが `node` の受信を許可しているか（許可 or 一時オフ）。
- **ショートカットのNFCオートメーションは個人自動化用途**：iOSバージョンにより実行時に確認が挟まることがあり、不特定多数が自由に触る展示だと滑らかさに欠ける場合があります。来場者が自由に触る運用まで見据えるなら Core NFC + 自作アプリ（要 Developer Program）が候補になります。
- このMVPが検証するのは「**タグごとに違う結果を返せるか**」まで。まずここを確かめてから、運用方式を判断するのが狙いです。
