# 活字パズル

反転した活字ブロックの裏面に貼った **ArUco マーカー**をカメラで読み取り、
並べた順に文字（ことば）として認識する、物的な文字入力インターフェース。
印刷博物館の活字拾いの展示を参照し、IC チップの代わりに ArUco マーカーで
MacBook / iPad だけで実現している。

## 2つのバージョン

| フォルダ | 用途 | 内容 |
|---|---|---|
| `./`（ルート） | ことばづくりゲーム | レベル別の出題語をブロックで組んで正誤判定。タイマー付き |
| `./シンプル版/` | 展示・投影用 | 検出したかなを 2:1 スクリーンに角度そのまま描画＋上部に横並び表示 |

## 実行方法

`getUserMedia`（カメラ）と ES モジュールの都合で、**ローカルサーバ経由**で開く必要がある（`file://` では動かない）。

```sh
cd 活字パズル
python3 -m http.server 8000
# → http://localhost:8000/            （ゲーム版）
# → http://localhost:8000/シンプル版/  （投影版）
```

背面カメラ（environment）を使うため、スマホ／タブレットでの利用を想定。

## 操作（ゲーム版）

1. **カメラを準備する** → **ゲーム開始**
2. 出題語が大きく表示される。手元でブロックを並べる
3. **カメラ / 出題 切替**でカメラ映像を確認。置いた活字が刷り上がりとして重なって見える
4. **決定**で正誤判定。全問正解で `CLEAR!`

右上の ◐ で**ライト / ダーク**切替（sumi の2モード）。

## にじみ — テンプレとのずれが刷りの質になる

出題語は「何を組むか」であると同時に、**理想の組版**でもある。
水平・等間隔・角度ゼロからのずれを弾く代わりに、**にじみ**として刷り上がりに出す。
活字を雑に組むと印圧が揃わずインクがにじむ、という活版の身体性をそのまま画面に持ち込んでいる。

- 揃えて置く → くっきりした 1 枚
- 雑に置く → ぼけて、**ずれた方向へ版が重なる**（版ズレ）

### テンプレの組み方

画面上の絶対位置は決め打ちにしない（どこに置いても成立させるため）。
検出したブロック自身から「あるべき並び」を組む。

- **水平**なベースライン（中心の平均 y）
- **等間隔**（隣り合う間隔の中央値。1個しか無いときはブロック辺長 × 1.4）
- **角度ゼロ**
- 全体の中心は検出ブロックの重心

案内として、ベースラインと出題語の文字数ぶんのスロットを薄く重ねて描く（`showTemplate`）。

ずれの測定は**置いた数ぶん**のスロットで行う。出題語の文字数で測ると、
3 文字の出題に 2 個しか置いていない人が半コマぶん常にずれてしまい、
置き方の丁寧さを測れなくなるため（`template.js` の `fitSlots`）。

### にじみ量

```
位置ずれ = |実際の中心 − スロット中心| / ブロックの辺長
傾き     = |angleRad|
にじみ量 = clamp(max(位置ずれ / fullOffset, 傾き / fullAngleDeg), 0, 1)
```

**悪いほう**を採る。足し合わせるとどちらも中くらいのときにすぐ上限へ張り付き、
丁寧さの差が見えなくなるため。

各ブロックのにじみ量の平均を「**組版の乱れ**」としてステータスに出す。調整は `config.js` の `bleed`。

### 傾きの扱いを変えた

以前は傾き 5 度を超えた活字を単語から**除外**していた（`angleLimitDeg`）。
いまは `angleTolerantDeg: 35` まで単語に数え、傾きは弾かずににじみへ回す。
35 度を超えるものだけ「まだ置いていない／誤検出」として外す。

正誤判定は従来どおり「どの字を並べたか」だけを見る。
にじみは**置き方の質**を表す別の軸で、正誤には影響しない。

## UI（sumi デザインシステム）

見た目は `sumi`（`CLdev/sumi-ui`）の墨基調トークンに準拠。UI は ZEN Interface、
**活字そのもの（出題語・読み取り語）は Mincho serif** で「活字」らしさを残している。
ゲーム版はライト既定＋◐でダーク、投影版は投影用に常時ダーク（`data-theme="dark"`）。
`sumi-tokens.css` は `CLdev/sumi-ui/src/styles/tokens.css` の同梱コピー（更新時は再コピーで同期）。

## ファイル構成

```
sumi-tokens.css … sumi デザイントークン（同梱コピー・light/dark）
style.css       … ゲーム版スタイル（sumi トークン参照）
aruco-core.js   … OpenCV.js 読み込み・カメラ起動・ArUco 検出（共通コア）
config.js       … 出題設定（レベル別の語・出題数・傾き許容角・にじみ）
template.js     … 出題語から理想の組版を組み、ずれを測る（純粋関数）
renderer.js     … カメラ映像への重ね描き（にじみ・版ズレ・案内線）
ui.js           … DOM の取り回し（ツールバー・ステータス・ログ・テーマ）
script.js       … 本体（起動・ゲーム進行・検出ループ）
シンプル版/style.css  … 投影版スタイル（sumi ダーク）
シンプル版/config.js … 投影の表示設定（解像度・フォント）
シンプル版/script.js … 投影表示（にじみは入れていない）
```

- **マーカー ID → かな文字の対応**は `aruco-core.js` の `KANA_BY_MARKER_ID` に一元化。
  新しいブロックを足すときはここだけ直せば両版に反映される。

## メモ

### OpenCV.js を `await` してはいけない（2026-09-06 に踏んだ罠）

`loadOpenCv` が `cv = await cv` としていたため、**ページが真っ白のまま固まり**、
「opencv.js を読み込み中…」から進まなくなっていた。Chrome でも再現した。

原因は Emscripten のモジュールの形。`window.cv` は thenable なのだが、
**解決値が自分自身で、しかも `then` を持ったまま**返ってくる。

```js
factory.then((m) => {
  m === factory        // true
  typeof m.then        // 'function' ← まだ thenable
});
```

`await` や `resolve()` に渡すと、Promise の解決手続きが
「thenable だから解決する → 解決値がまた thenable → …」を延々と繰り返し、
メインスレッドが二度と返らない。タイマーも描画も止まるので、
ページが固まったようにしか見えない。

対処は 2 つ。

1. **`.then()` のコールバックで受ける**（`await` しない）
2. 受け取ったら **`then` を外す**（`detachThen`）。外さないと、呼び出し側が
   await した時点で同じ穴に落ちる

Node で `.then()` を使って試すと 360ms で読み込めてしまうため、
「ライブラリも URL も正常なのにブラウザだけ固まる」という切り分けにくい形で出る。
