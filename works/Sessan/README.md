# Sessan（空中タイピング）

手のジェスチャと表情（口形・目）だけで、キーボードに触れずにかなを入力する試み。
MediaPipe Holistic で手・顔を同時に追跡する。

## 実行方法

カメラと ES モジュールの都合で **ローカルサーバ経由**で開く（`file://` 不可）。

```sh
cd Sessan
python3 -m http.server 8000
# → http://localhost:8000/
```

## iPad / iPhone から開く

**カメラは HTTPS でしか動かない**。`getUserMedia` は安全なコンテキストを要求するので、
`http://<MacのIP>:8000` を Safari で開いてもカメラの許可が出ない。
LAN の IP に公的な証明書は取れないので、ローカル CA を作って自分で署名する。

プロジェクト直下の `ipad-serve.sh` がそれを全部やる。

```sh
./ipad-serve.sh                       # 既定で Sessan を配る
./ipad-serve.sh SourceCode/works/Xxx  # 別の作品を配るとき
```

起動すると iPad 用の手順を IP 入りで表示する。要点だけ:

1. iPad の Safari で `http://<IP>:8442/ca.crt` → プロファイルがダウンロードされる
2. 設定 → 一般 → VPN とデバイス管理 → インストール
3. **設定 → 一般 → 情報 → 証明書信頼設定 → オン** ← ここを忘れるとカメラが出ない
4. Safari で `https://<IP>:8443/`

1〜3 は最初の一回だけ。DHCP で IP が変わっても、スクリプトが証明書を作り直してから起動する。

- 証明書は `.certs/`（git の外。SourceCode リポジトリには入らない）
- SAN に IP を入れてある。**Safari は CN を見ないので SAN が必須**
- 有効期間は 398 日。Apple がそれを超える TLS サーバ証明書を弾くため

### iPad で気をつけること

- **MediaPipe を CDN から読んでいる**（`cdn.jsdelivr.net`）。
  会場の Wi-Fi が外に出られないと動かない。展示で使うなら先に手元へ置くこと
- **保持の判定がフレーム数**（`HOLD_FRAMES` は 22 フレーム、`FINGERS.voteFrames` は 7 フレーム）。
  iPad が 15fps しか出なければ、確定までの時間は倍になる。
  時間で測るように直すかどうかは、実機の fps を見てから決める
  （心拍だけは経過秒で進めているので、fps が落ちても bpm は狂わない）

## 操作

| 動作 | 割り当て |
|---|---|
| 指の本数（両手合計 1〜10） | **行**（あ／か／さ…わ行） |
| 口の形（あいうえお） | **段**（母音） |
| 同じ字を保持（約22フレーム） | その字を**確定入力** |
| 目を閉じて保持（約25フレーム） | **1字削除**（バックスペース） |
| グーを保持（約30フレーム） | 末尾に**濁点**（片手）／**半濁点**（両手） |

確定中の字は**画面の中央に、薄く大きく重ねて描かれる**。顔を近づけるほど大きく、
保持するほど濃くなる（確定が近いことが字そのものに出る）。
さらに字は**縦の短冊に切られ、心拍の位相で一本ずつ上下にずれる**。右下のチップは状態表示。

- ステージ右上の **「較正」** で口形の較正、↺ で較正を初期値に戻す（較正済みのときだけ出る）。
- ⚙ で HUD（指・母音・確定/修飾メーター・目）の表示を切り替え。
- ◐ で **ライト / ダーク**切り替え（sumi の2モード）。
- 画面はヘッダーなしのコンパクト構成。

## 指の数え方（向きに依らない量だけで見る）

以前は「指先が第二関節より y 上なら立っている」で数えていた。
これは**手をまっすぐ上に向けている前提**で、傾けると崩れる。親指も y で見ていた。

合成した手（32通りの指の組み合わせ × 回転 × 鏡像）で測った結果:

| | 0° | 20° | 45° | 90° |
|---|---|---|---|---|
| 以前 | 100% | 50% | 50% | 19% |
| いま | 100% | 100% | 100% | 100% |

いまは向きに依らない量だけを使う。

- **人差し〜小指** … 付け根→第二関節 と 第二関節→先端 の**向きの変化角**。
  まっすぐなら 0、曲げるほど大きい。手を回しても角度は変わらない
- **親指** … 手のひらの「横」向き（人差し指の付け根→小指の付け根）を基準に、
  親指がその逆向きへどれだけ開いているか。**左右の手でも鏡像でも、
  基準と親指が一緒に反転するので符号の関係が保たれる**（y のしきい値と違って場合分けが要らない）

しきい値は `config.js` の `FINGERS`。`bendDeg` は 40〜80° のどこでも成績が変わらなかったので
真ん中の 60° を置いてある。

### 効いたのは正答率より「読みが変わる回数」

本数が1フレームでも変われば選択字が変わり、**22フレームの保持が振り出しに戻る**。
1秒に何度も変われば永久に確定しない。体感の「精度が悪い」の正体はこちら。

追跡のぶれ（σ＝手の大きさの2%）を入れて 10 秒流したときの、読みが変わった回数:

| | 変化回数 |
|---|---|
| 以前 | 61.5 回 |
| いまの判定のみ | 0 回 |
| いまの判定＋多数決 | 0 回（ぶれ 5% でも 0 回） |

`FingerVote` が直近 `voteFrames`（既定 7 ＝ 30fps で約 0.23 秒）の**最頻値**を返す。
同数なら今の値を保つので、きっかけの無い入れ替わりが起きない。
確定の保持 0.73 秒に対して遅れは 1/3 に収まる。

### ここまでで解けていないこと

- **奥行き方向の傾きは苦手**。指をカメラ側へ向けると 2D では短く写るだけなので、
  曲げているのか手前を向いているのか区別がつかない。上の数字は**画面内の回転**の話
- 測ったのは**合成した手**。回転とぶれに強いことは示せたが、**実写の精度ではない**
- MediaPipe Holistic（旧 solution 系）の手のランドマークは、
  姿勢から切り出して求めるぶん専用の手モデルより粗い

奥行きまで要るなら、Tasks API の **world landmarks**（手を基準にした3D座標）へ移るのが筋。
`@mediapipe/tasks-vision` の `HandLandmarker` / `GestureRecognizer` / `HolisticLandmarker` が返す。
**Gesture Recognizer の既定カテゴリ（`Closed_Fist` `Open_Palm` `Pointing_Up` `Thumb_Up`
`Thumb_Down` `Victory` `ILoveYou` `None` の8つ）に指の本数は無い**ので、
そのままでは行の判別には使えない。使うなら Model Maker で自前に学習させることになる。
移る理由があるとすれば、カテゴリではなく world landmarks のほう。

## 母音の判別（口腔の面積 + 縦横比）

先行研究が母音判別に有効としているのは、口の縦横の長さそのものではなく
**口腔の面積と縦横比**の組み合わせ。

- Lyons, Chan, Tetsutani "MouthType: Text Entry by Hand and Mouth" CHI 2004 — 日本語の音節が
  基本的に C+V であることを使い、子音＝手、母音＝口に割る。口の面積と縦横比を離散状態へ変換し、
  話者ごとに範囲を較正する
- Saitoh, Hisagi, Konishi (2007) IEICE — 15 種の特徴量を比較し、口腔の面積 + 縦横比を含む組が有効
- KUCHIMOJI (2026) — MediaPipe で唇 ROI を切り出し、5 母音 + 閉唇 N の 6 クラスへ

これに合わせて特徴量を差し替えた。

| 以前 | いま |
|---|---|
| `v` = 上下唇間距離 / 顔サイズ | `area` = **内唇リングの多角形面積** / 顔サイズ² |
| `h` = 口角間距離 / 顔サイズ | `aspect` = 口の縦幅 / 横幅 |

- 面積は FaceMesh の内唇リング 20 点をシューレース公式で解く（`INNER_LIP_RING`）
- **顔サイズ²で割るのでカメラとの距離に依存しない**。近づいても母音の判定は変わらない
- 分類は最近傍だが、面積と縦横比は桁が違うので、各軸をターゲット値の幅で割ってから比べる
  （単位を揃えているだけで、較正ではない）
- 閉唇 `close` は 6 番目のクラスとして残してある（KUCHIMOJI の N クラスにあたる）

CNN は使っていない。論文の言うとおり、**単純な幾何特徴だけで 5 母音は分けられる**。

## 較正

`VOWEL_TARGETS` は手調整の定数なので、別の人が試すと合わない。
◎ を押すと、**あ・い・う・え・お を順に 1 秒ずつ保持**して、その間の
`(area, aspect)` の平均を各母音のターゲットにする（構える時間 0.8 秒 → 取り込み 1 秒）。

- 結果は `localStorage` に保存し、次回起動時に読む
- ↺ で初期値に戻す
- **較正しなくても既定値で動く**。あくまで上書き
- 較正しない `close` は既定値のまま残る（口を閉じれば面積はほぼゼロになるので較正が要らない）

やっているのは 5 つの平均を取ることだけ。最大最小の正規化や話者ごとの分散の吸収、
時間変化（HMM / DTW）には踏み込んでいない。設定は `config.js` の `CALIBRATION`。

## 心拍で字の位相をずらす

確定中の字を**縦の短冊（既定 16 本）に切り、一本ずつ上下にずらす**。
ずれは短冊をまたいで左から右へ進む正弦波で、その位相を**心拍**が進める。

- **拍の合間はほぼ揃い、脈が来た瞬間にいちばん割れる**（振幅を脈波で変調している）
- 谷でも `pulseFloor` ぶんのずれは残す。0 にすると拍の間だけ字がぴたりと整う
- 字は一度オフスクリーンに刷ってから短冊で切り出す。同じ字・同じ大きさのあいだは
  刷り直さないので、毎フレームの `fillText` は発生しない
- 切れ目は `Math.round` で隣と突き合わせる。重ねないので、薄い色でも継ぎ目が濃くならない
- 縁に敷く地色の暈しは刷り込みに**焼き込む**（短冊ごとに shadow を掛けると 16 回ぶんの影処理になる）

設定は `config.js` の `GLYPH`。`slices` / `waveTurns` / `shiftRatio` / `pulseFloor` /
`alphaMin` / `alphaMax` / `haloRatio`。

### 心拍そのものは、まだ合成波

**センサは載せていない**。`heartbeat.js` が、ヒトの範囲で揺れる信号を自前で作る。

| 成分 | 中身 |
|---|---|
| `bpm` | 基準値に、呼吸性洞性不整脈（0.22Hz ≒ 13回/分）± ゆっくりした漂い ± 細かいゆらぎ |
| `phase` | bpm を積分して進める。bpm が上がれば拍の間隔も詰まる |
| `pulse` | 脈波（PPG）に似せた包絡。収縮期のピークと、少し遅れて来る重複隆起 |
| `beat` | 位相が一周した瞬間 |

実センサ（PPG / HRV バンド等）に差し替えるときは、`sample()` が返す
`{ bpm, phase, pulse, beat }` の形だけ合わせればよい。**位相を使う側（renderer）は
信号の出どころを知らない。**

#### 揺れの大きさは、作る側の裁量ではない

心拍の揺れ（HRV）は身体の状態で決まる。適当に大きくすると**嘘になる**ので、
プリセットを3つ用意して、5分ぶん回した実測値を添えてある。

| preset | 平均 | bpm範囲 | SDNN | RMSSD |
|---|---|---|---|---|
| `focus` **（既定）** | 84 | 78–89 | 24ms | 15ms |
| `rest` | 68 | 62–75 | 38ms | 31ms |
| `loose` | 68 | 56–80 | 75ms | 48ms |

既定を `focus` にしてあるのは、**Sessan を使っている人は安静ではない**から。
手を上げ、口の形を作り、見られながら集中している。
この状態では心拍は上がり、揺れはむしろ**小さくなる**（認知的負荷で迷走神経の働きが下がる）。
「生体信号だから大きく揺れるはず」という直感とは逆になる。

`loose` は見た目の揺れを稼ぐための値で、座った人の生理としては過剰。
それでも使うなら、**そう決めて使っていることを言えるようにしておく**。

設定は `config.js` の `HEARTBEAT_PRESETS` と `HEARTBEAT`。

## 見え方を詰める（カメラ不要）

`_preview-glyph.html` — **カメラを使わずに**、字のずれと心拍をスライダで動かしながら見る。

```sh
python3 -m http.server 8000
# → http://localhost:8000/_preview-glyph.html
```

- 字: 短冊の本数・波の数・ずれの量・谷に残すずれ・不透明度・縁の暈し
- 心拍: プリセット・基準 bpm・揺れの倍率
- **HRV（SDNN / RMSSD）をその場で実測して出す**（直近60拍の拍間隔から）。
  揺れを盛ったときに、それが身体としてありえる値かどうかがその場で分かる

### プレビューと本番は同じ値で動く

スライダを動かすと **localStorage に即保存され、`index.html` も起動時に同じ値を読む**。
別々の設定を持って食い違う、ということが起きない。

- 上書きが効いているときは、本番の HUD に **「調整中」** と出る
- **↺ 既定値に戻す** で上書きを消す（`config.js` の値に戻る）
- **config.js 用に出す** で貼り付けられる形に書き出す。恒久化するときはこれを貼る

読み書きは `tuning.js`。キーは `config.js` の `TUNING`。
既定値に無い鍵と型の合わない値は捨てるので、古い保存が残っていても本番は壊れない。
保存が使えない環境（プライベートモード等）では既定値のまま動く。

確認用なので `_preview-glyph.html` は消してよい。消しても本番は動く。

## 顔の近さ → 字の大きさ

`analyzeFace` が返す `proximity`（左右の目尻の間隔）をそのまま近さとして使う。
母音の判別で顔サイズを基準に使っているので、**近さの計測を別に足す必要はなかった**。

`PROXIMITY` の `far`〜`near` を `minPx`〜`maxPx` へ写し、外側は頭打ちにする
（既定では近さ 0.10 で 240px、0.32 で 620px）。合わなければ `config.js` を直す。

**字は薄く重ねる前提なので大きく取ってある**（以前は 90〜480px）。
不透明度が低いので、顔の上に乗っても顔を隠さない。

## 表示サイズをドラッグで変える

ステージ右下のつまみを引くと**縦横が変わる**。ダブルクリック／ダブルタップで既定に戻る。

- Pointer Events なので、マウスでも iPad の指でも同じように動く
  （つまみに `touch-action: none` が要る。無いと iPad では画面のほうがスクロールしてしまう）
- 映像は canvas の `object-fit: contain` なので、**比を変えても歪まない**。
  入りきらないぶんは地色の帯になる
- カメラの比に 6% まで近づいたら**その比へ吸い付く**。帯の出ない大きさを取りやすくするため
- 下のパネルもステージの幅に揃う（`--content-w` が `--stage-w` を見ている）
- 大きさは `localStorage`（`sessan.stageSize.v1`）に憶える。
  次に開いたとき画面が小さくなっていれば、その場で画面内に挟み直す

寸法は CSS 変数 `--stage-w` / `--stage-h` で持つ。
既定値は下の「高さ上限から幅を逆算」で、ドラッグしたときだけ JS が `:root` に px を直接入れて上書きする。
**renderer は比（`--cam-ar`）だけを渡し、寸法には触らない**。
触ると、つまみで決めた縦横を毎フレーム上書きしてしまう。

## 表示サイズの既定（iPad 縦置きで高くなりすぎない）

映像は**ネイティブ比のまま等倍**で表示する（切り抜き・余白・歪みのいずれも無し）。
そのうえで**ステージの高さに上限**を設け、**幅をその高さと比から逆算**するため、
iPad 縦置きでもカメラ表示が縦に伸びすぎない。

- 高さ上限は `style.css` の `--stage-max-h`（既定 `44vh`）で調整
- 幅は `--stage-w = min(560px, 100%, var(--stage-max-h) * var(--cam-ar))`。パネルも同じ幅で揃う
- カメラ比 `--cam-ar` は初回フレームで JS（`syncFrameSize`）が実解像度から設定

実測（768×1024 の iPad 縦置き）: 16:9 カメラで 560×315、4:3 で 560×420。
縦が短い横置き（1024×768）では高さ上限が効いて 4:3 が 451×338 に収まる（比は保ったまま）。

## 記録（字形＋顔）

文字を確定するたびに、その瞬間を**2枚**で記録する。

| | 中身 |
|---|---|
| **字形** | そのとき画面に出ていた字を、**心拍の位相ごと**焼き付けた PNG |
| **顔** | そのときのカメラ全体フレームを縮小したもの |

字形は `Renderer#captureGlyph` が作る。**画面と記録は同じ `#paintSlices` で描く**ので、
記録に残るのは「見えていた形」そのもの。倍率を掛けているだけで、
位相・振幅・短冊の割り方はいっさい変えていない。

- 地の色は**焼き込む**。あとでテーマを切り替えても、記録は撮った時のまま残る
- 不透明度は画面と別（`GLYPH.recordAlpha`、既定 1）。画面は薄いが、記録は形を見るものなので濃く刷る
- 字の下に、そのときの **bpm** を併記する。字形がその形をしている理由が記録の中で完結する

### ビューの切り替え

記録の見出しの右のピルで **字形 / 顔 / 両方** を選ぶ。
**記録そのものは常に両方を持っていて**、切り替えているのは CSS の出し分けだけ
（`.filmstrip[data-view]`）。あとから見たい側に変えても、撮り直しは起きない。
選択は `localStorage` に憶える。

### そのほか

- バックスペースで末尾の記録も1件戻る
- 濁点／半濁点では、**確定したときと同じ位相で字形を刷り直す**（顔は撮り直さない）。
  バックスペースの直後だけは刷り直す先が無いので、ラベルだけ変える
- **このセッション内の画面表示のみ**（ファイル/DB への保存はしない）

設定は `config.js` の `SNAPSHOT`（横幅・枚数上限）と `GLYPH.recordAlpha`。

## UI（sumi デザインシステム）

見た目は `sumi` デザインシステム（`CLdev/sumi-ui`）の墨基調トークンに準拠。
`sumi-tokens.css`（`CLdev/sumi-ui/src/styles/tokens.css` の同梱コピー）を読み込み、
色はすべて `--color-*` セマンティックトークン参照。書体は ZEN Interface（未読込時は system-ui）。
※ sumi 側を更新したら `sumi-tokens.css` を再コピーして同期すること。

```

typing-core.js  … 指数え（向きに依らない判定）・FingerVote（多数決）・口腔の面積/縦横比・母音分類・HoldGate ※MediaPipe 非依存の純粋関数
```

## メモ

- `VOWEL_TARGETS` の既定値は、以前の手調整値（縦開き比 v / 横幅比 h）から
  `aspect = v/h`、`area ≒ (π/4)·v·h` として換算した**出発点**。
  ただし閉唇は、内唇リングが潰れて面積がほぼゼロになるので実態に合わせて小さくしてある。
  実際に合わせるのは ◎ の較正のほう。
- 目の開閉（`EYE_TARGETS`）は手調整済みの値のまま。較正の対象にしていない。
- MediaPipe Holistic は旧 solution 系 API。挙動維持のため意図的にそのまま採用している。
- **心拍はまだ本物ではない**。いま見えている揺れは全部こちらで作った波。
  センサを載せるまで、これで語れるのは「位相が字に出るとどう見えるか」までであって、
  「その人の心拍が字に出る」ではない。
- 揺れの大きさは**プリセットの実測値（SDNN / RMSSD）で裏を取ってある**。
  ただし、それは「作った波が生理的にありえる範囲か」を確かめただけで、
  実在の誰かの心拍を再現したものではない。ここを混ぜて語らないこと。
