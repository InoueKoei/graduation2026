# DanceToggle

ケータイの**トグル（かなめくり）入力**を、USB ダンスマットの上に置き換えたもの。
指のタップが足の踏み込みになる。「あ」は1回、「お」は5回踏む。「る」は3回。

速く打つための入力ではない。**1文字に何回踏むか**がそのまま身体の運動量になり、
「お」や「そ」のような後ろの段の字ほど、打つのに大きく動くことになる。
入力の結果ではなく、入力している過程のほうを見るための作りにしてある。

## 実行方法

ES モジュールの都合で**ローカルサーバ経由**で開く（`file://` 不可）。

```sh
npx --yes http-server SourceCode/works/DanceToggle -p 8987 -c-1
# → http://localhost:8987/
```

Chrome で開く。マットは USB で挿すだけでよい（ドライバ不要）。
**接続直後は `navigator.getGamepads()` が `null` を返すことがある**ので、
一度どこかの面を踏むと認識される。画面上部の帯に接続状況が出る。

## モード

画面右上で切り替える。

| モード | 中身 |
|---|---|
| フリー入力 | 自由に打つ |
| タイムアタック | 出されたお題を全部打ち切るまでのタイムを計る |
| 二人 | **マット2台**。子音（行）と母音を二人で分担して1文字にする |

二人モードでは、ずれの見せ方（大きさ／ぼかし／短冊）と、それに重ねる字幅の入／切を画面から選べる。

## 操作

| 面 | 役割 |
|---|---|
| 外周の8面 | あ〜や の各行。同じ面をくり返し踏むと段が進む |
| **中央** | **文字には使わない。立って休む場所（home）** |
| **中央を2度踏む** | 濁点・半濁点・小文字（直前の字に掛ける） |
| START | ら行 |
| SELECT | わ行（わ・を・ん・ー） |
| SELECT + START 同時 | 1字削除 |

- **面に乗る** → 既定 250ms 踏み続けて、はじめて入力になる（後述「移動の途中で踏んだ面を落とす」）
- **同じ面を踏み直す** → こちらは 80ms でよい。移動していないぶん軽い
- **同じ面をもう一度踏む** → 環を1つ進める。末尾まで行くと先頭に戻る（あ行を6回踏めば「あ」）
- **別の面を踏む** → 未確定の字を確定してから、新しい面の1字目を保留する
- **何も踏まずに待つ** → 既定 1000ms で自動確定

濁点・半濁点・小文字は iOS の `^^` と同じで、**ひとつの環**にまとめてある
（は→ば→ぱ→は、つ→づ→っ→つ）。保留中の字にも確定済みの末尾の字にも掛かる。
印を掛けたあとで同じ面をもう一度踏むと印は落ちる（ば → ひ）。ケータイと同じ。

## 中央は空けておく — 立って休む場所が要る

ダンスマットの中央は**立って休む場所**で、ここに文字を割り当てると成立しない。

はじめは中央を「な行」にしていたが、踏んでいるあいだ1回しか出ないようにしても足りなかった。
問題は連射ではなく、**休むために中央へ戻るたびに1字打たれる**こと。
「離してから踏み直す」を条件にしても、戻るのはまさに踏み直しなので防げない。
面ごと空けるしかない。

中央は1回踏んでも何も起きない。**2度踏む**と濁点・半濁点・小文字になる。
home にいながらその場で踏み直すだけなので動作としては一番軽く、
濁点は頻度が高いのでここに割り当てている。

**間に他の面が1つでも受け付けられたら成立しない。**
時間（`homeDoubleMs`、既定 900ms）だけを条件にすると、
よそを踏んでから中央へ戻ってきただけで濁点が出てしまうため。

## 配列の導出 — なぜ180°回すのか

マットは **180°回して床に置く**（ケーブル側が奥、踏む人はマットの裏側から乗る）。
その向きでケータイのテンキーを重ねると、ほぼそのまま重なる。

中央を空けたぶんは、**後ろの行を1つずつ繰り上げる**。
読み順（左上から右へ、上から下へ）に あ→か→さ→た→な→は→ま→や→ら→わ と並べ、
中央だけ飛ばす。五十音の順がそのまま残るので、中央を抜いたことさえ覚えていれば読める。

```
踏む人から見た盤面        マットの印
 あ   か   さ            □   ↓   △
 た （休） な            →   ●   ←
 は   ま   や            ○   ↑   ✕
 ら       わ           START     SELECT
```

検算：`□×1=あ`、`□×5=お`、`✕×3=ゆ`（や行3字）。

画面右の盤面も同じ向き（踏む人から見た向き）で描いてある。
各マスにはマット表面の印（□ ↓ △ …）を付けたまま動かしてあるので、
「画面のこのマスは足元のこの印のパネル」と照合できる。

配列を戻したくなったら `config.js` の `MAT_TO_ROW` を `ROW_LAYOUT.normal` に差し替える。
どちらが身体に馴染むか実機で比べたいので、両方残してある。

### 句読点を落とした理由

ケータイの12キーには `、。?!` があるが、これは落とした。

マットの入力は11個（3×3 ＋ SELECT ＋ START）。そこから中央を home に抜くと**10個**しか残らず、
要るのは **10行 ＋ 濁点 ＋ 削除 ＝ 12**。2つをジェスチャに逃がすことになり、
濁点を「中央の2度踏み」、削除を「SELECT+START の同時踏み」に割り当てた。
句読点を残す余地はもう無い。

そのぶん削除は **SELECT + START の同時踏み**にした。
左上と右上を両足で同時に踏む、という大きな動作になるので、
「消す」の身振りとしてもちょうどよい。

## タイミング

6つの時定数がある。いずれも `config.js` の `TIMING`、`bothMs` 以外は画面のスライダでも動く。

| 値 | 既定 | 理由 |
|---|---:|---|
| `holdMs` | 250ms | **新しい面**に乗ってからこの時間だけ踏み続けて、はじめて入力になる。移動の途中で通過した面を落とすための溜め |
| `repeatHoldMs` | 80ms | **同じ面を踏み直す**ときの溜め。移動が無いぶん短くてよい |
| `homeDoubleMs` | 900ms | 中央（home）を2度踏みとみなす猶予。間に他の面が入ったら成立しない |
| `commitMs` | 1000ms | 最後の踏みからこの時間で自動確定。ケータイのトグルは 800ms 前後だが、足は指より1ストロークが遅いので長めから始める |
| `releaseDebounceMs` | 60ms | 離れてからこの時間内の踏みを、同じストロークの跳ね返りとみなす |
| `bothMs` | 180ms | SELECT+START を「同時」とみなす猶予 |

### 移動の途中で踏んだ面を落とす — `holdMs`

マットは9面が隣り合っているので、**次の面へ足を運ぶ途中で通過した面も踏まれてしまう**。
「あ」から「ら」へ行くには対角に足を運ぶことになり、そのあいだの面が全部入力になる。

通過は短く、入力のために乗るのは長い。この差で切り分けている。
ここに届く前に足が離れた面は、通過だったとみなして一度も入力に通さずに捨てる。

**250ms という数字はまだ計っていない。**
「歩いて通過するのは 100ms 前後、着地して乗るのは 200〜400ms 続く」という
一般的な見積もりから間を取っただけの出発点で、このマットで測った値ではない。
実際に踏んで、通過が拾われなくなり、かつ連打が重くならない値を探すこと。

画面の盤面では、乗っている面に**下から墨が満ちる**。満ちきった面だけが反転して「入った」ことを示す。
通過した面は途中まで満ちて消えるので、拾われなかったことがその場で分かる。
`holdMs` を詰めるときはこの満ち方を見ながら合わせる。

`commitMs` より長くすると次を踏む前に勝手に確定してしまうので、
`holdMs` を上げたら `commitMs` も一緒に上げること。0 にすればこの機能は切れる。

### 新規と踏み直しで溜めを分ける — `repeatHoldMs`

はじめは新規も踏み直しも同じ溜めにしていたが、これは払わなくていいコストだった。

**溜めが要るのは移動があるからで、通過してしまう面があるのは「別の面へ足を運ぶ」ときだけ。**
同じ面を踏み直しているあいだは足がその面から動いておらず、通過の危険がない。
そこで、直前に受け付けたのと同じ面を踏み直したときだけ、短い溜め（既定 80ms）で通す。

効きは大きい。「お」は5回踏むので、

```
全部 250ms      → 250 × 5        = 1250ms
踏み直しを 80ms → 250 + 80 × 4   =  570ms
```

その場の小さな跳びは接地が 100ms 前後なので、それより短い 80ms を出発点にした。

**期限がある。**短い溜めで通してよいのは「その字をまだ回している最中」だけなので、
有効期限は確定待ち（`commitMs`）と同じにしてある（`script.js` が同じ値を入れている）。
そこを離れてしばらく経ってから戻ってきた踏みは、踏み直しではなく移動なので、
新規と同じ `holdMs` が要る。

要る溜めは**踏み始めた瞬間に決めて**その踏みに持たせている。
途中で判定が変わると、乗っている最中に受付の条件が動いてしまうため。

### `releaseDebounceMs` が要る理由

マットの接点は薄い金属箔で、着地の衝撃で ON/OFF が数ミリ秒のあいだに往復する（チャタリング）。

`holdMs` を入れたことで、この値の役割は「2回に数えない」から
**「跳ね返りのたびに溜めを 0 から数え直さない」**に変わった。
数え直してしまうと、チャタリングの多い面はいつまでも `holdMs` に届かず、
いくら踏んでも入力にならない。
離れてから `releaseDebounceMs` 以内に戻ってきた踏みは同じストロークの続きとみなし、溜めを引き継ぐ。

### SELECT と START の区別

SELECT と START は、単体なら「わ行」「ら行」、同時なら「削除」。
両足で踏むので完全同時にはならず、片足ずつ 50〜150ms ずれる。
区別するには、片方が来た時点では確定させずに相方を待つしかない。

`holdMs` を入れてからは、待つ必要がほとんど無くなった。
片方の溜めが満ちる頃には、もう片方はすでに足の下にあるので、その場で同時踏みと判定できる。
相方がまだ来ていないときだけ、足りない分（`bothMs` − `holdMs`）を待つ。
既定では `holdMs` のほうが長いので、**待ち時間は 0**。`holdMs` を 0 にしたときだけ `bothMs` が効く。

## タイムアタック

`GAME.phrasesPerRun`（既定5文）のお題が引かれ、**全部打ち切るまでのタイム**を計る。
**最初の踏みで計測が始まる**（正解でもミスでも）。位置につくまでの時間を計らないため、
モードに入った時点では始めない。

### 「お題の入力しか受け付けない」をどこで切るか

素直に「お題と違う字は入れない」にすると破綻する。
トグルは**目的の字に着くまで必ず違う字を経由する**（「う」を出すには あ・い を通る）ので、
経由の字まで弾いたら誰も何も打てない。

そこで、受け付けの門を**行のところに置いた**。

- **行が違う面** … 受け付けない。ミスとして数え、その面を一瞬反転させて知らせる
- **段（何回目か）** … お題の字と一致するまで自由に回してよい
- **一致した瞬間に確定** … 待たない

副産物として、ゲーム中は**確定待ち（`commitMs`）が消える**。
一致した瞬間に次の字へ進むので、1字ごとに1秒待つ必要がない。
同時に、目的の字を**通り過ぎることが起きない**（通った瞬間に確定するため）。

印（SELECT）は、掛ける相手が無いのに踏んだときだけミスになる。
保留中の字に掛けるぶんには、間違った字が確定することはないので数えない。

### ミスはタイムに響かない

ミス1回ごとにペナルティ時間を足す作りにはしていない。
足で踏む入力は、踏み間違いを恐れると動きが小さくなる。
**恐れずに動けるほう**を取って、ミスは記録するだけにしてある。
ペナルティを入れたいなら `script.js` の `handlePress` のミス処理に足す。

### お題

`phrases.js` にひらがなの短文を入れてある。ロジックとは分けてあるので、ここだけ差し替えればよい。
制約が2つある。

1. **ひらがなと「ー」だけ**。句読点キーを落としてあるので打てない
2. スペースも打てないので分かち書きはしない

打てない字が混じっていないかは起動時に `validatePhrases()` が確かめ、
見つかれば console に警告を出す。踏んでみて初めて気づく事故を防ぐため。

## 二人モード — 子音と母音を分担する

**マットを2台**つないで、かな1文字を二人で作る。
「さ」を踏む人と「あ」を踏む人がそろって、はじめて「さ」になる。

既存作 [boin-shiin-mvp](../boin-shiin-mvp/)（子音＝PCキーボード／母音＝RP2040マクロパッド）の
マット版にあたる。許容時間差 1500ms もあちらで二人で打って決めた値を引き継いでいる。

### 割り当て

**子音マット（1台目）は今までのまま。** ただしトグルの環は回さない。
**1回踏めばその行に決まる**（「さ」を出すのに5回踏む必要はない。段は相方が決めるため）。

**母音マット（2台目）も子音マットと同じく 180°回して置く。** 二人とも同じ向きで乗るので、
画面もどちらも踏む人から見た向きで描ける。その向きだと母音は読み順のまま並ぶ。

```
   マット物理配置        踏む人から見た向き（＝画面）
   ×   ↑   ○            □   ↓   △        あ  い  う
   ←  CTR  →      →     →  CTR  ←   ＝   え （空）お
   △   ↓   □            ○   ↑   ✕       （使わない）
```

回さずに置きたくなったら `config.js` の `MAT_TO_VOWEL` を `VOWEL_LAYOUT.normal` に、
`VOWEL_PANEL_GRID` を `RAW_PANEL_GRID` に差し替える。子音側と同じく両方残してある。

中央を空けてあるのは、あ行5つを上段3つと中段の左右に散らして足を大きく運ばせるため。
中央に置くと母音側がほとんど動かなくなる。

| | 子音マット（スロット0） | 母音マット（スロット1） |
|---|---|---|
| 3×3 | 外周8面が あ〜や の各行。**中央は home** | 盤面どおり あ い う ／ え ・ お（他は未使用） |
| START | ら行 | 未使用 |
| SELECT | わ行 | 未使用 |
| 中央の2度踏み | 濁点・半濁点・小文字 | 未使用（中央は最初から空き） |
| SELECT+START | 1字削除 | 未使用 |

濁点は**相方を待たない一人の操作**。二人で作った字のあとに、子音側が一人で濁らせる。

### 成立しない組み合わせ

や行の「い」「え」、わ行の「い」「え」は五十音図に無いので字にならない。
踏まれた2つを画面に残したまま一瞬見せて、成立しなかったことを知らせる。

**「ん」だけは決め打ちで わ行 × う に置いた。** 現代かなではこの段が空いているため。
五十音図から導いたものではなく、置かないと「ん」がどうやっても打てないので入れた選択
（`config.js` の `DUO_KANA`）。これで現代かな46字がすべて打てる。

### 2台の区別 — index しか手がかりが無い

2台とも VID/PID も `id` 文字列も**完全に同一**で、
Gamepad API で違うのは `index` だけ。実測でこうなる。

```
index 0 : USB Joystick  (STANDARD GAMEPAD Vendor: 0079 Product: 0006)
index 1 : USB Joystick  (STANDARD GAMEPAD Vendor: 0079 Product: 0006)
```

index の昇順で「子音／母音」に割り当てているが、**どちらの物理マットが index 0 になるかは
USB の列挙順まかせ**で、こちらからは決められない。逆だったときのために
調整パネルに **「マットを入れ替える」** を置いてある。押すと役割が入れ替わり、
画面上部に `接続：子音=Joy1 / 母音=Joy0` のように出る。

### 判定はマットごとに独立

溜め（`holdMs`）・チャタリング除去・SELECT+START の同時踏み判定は、
すべて**スロットごとに分けて**持っている。二人が同時に別のマットを踏んでも、
互いの判定に干渉しない。

同時踏みの削除も**同じマットの中だけ**で閉じている。
子音マットの SELECT と母音マットの START を同時に踏んでも削除にはならない
（このとき子音マットの SELECT は単体＝わ行として働く）。

### 許容ずれ

`DUO.pairMs`（既定 1500ms）。片方だけ踏まれてこの時間が過ぎたら、その踏みは捨てる。
画面のスライダで 300〜4000ms まで動かせる。

**足なので指より要るかもしれない。** 1500ms は指（キーボードとマクロパッド）で決めた値なので、
二人で踏んでみて詰めること。成立した1文字ごとに実際のずれが画面に出るので、それを見ながら合わせる。

## 時間を字の姿にする

入力にかかった時間を、そのまま字の見え方に出している。速さの記録ではなく、
**打っているあいだに起きたことが字に残る**ようにするためのもの。

### 止まっていた時間 → 字の幅（フリー入力・タイムアタック）

**前の字を踏み終えてから、次の字を踏みはじめるまでの間隔**を測り、
長いほど**広い字**、短いほど**細い字**にする。
迷い・探り・立ち止まりが、そのまま字幅として残る。

変えるのは大きさではなく**字の横幅**。
組版の行が揃ったまま、字そのものの姿だけが平たくなったり細くなったりする。

```
間隔    0ms  →   50%（最も細い）
      400ms  →   59%
      900ms  →   80%
     1800ms  →  120%
     3000ms  →  150%（最も広い・頭打ち）
```

#### なぜ可変フォントの幅軸（`wdth`）を使わないのか

はじめは Momochidori VF（百千鳥、Adobe Originals／西塚涼子。`wdth` 50〜150 の幅軸を持つ）を
指定して、幅軸を振っていた。字面が崩れないので、書体としてはこちらのほうが正しい。

やめた理由は2つ。

1. **Adobe Fonts はフォントファイルを同梱して配れない。** その端末で Creative Cloud の
   フォントを有効にしてあることが前提になる。無ければ代替に落ちて、
   **幅が黙ってまったく効かなくなる**。展示先の機械でそれが起きると気づけない。
2. **軸の範囲がフォントの都合で決まる。** 50〜150 という幅は百千鳥が持っている幅であって、
   こちらが出したい幅ではない。

いまは軸に頼らず、`transform: scaleX()` で**字を横に引き伸ばす／縮めている**。
どのフォントでも必ず効き、50%〜150% の範囲もこちらで決められる。
引き伸ばした字は字面が崩れる——が、ここではその崩れ自体が「迷った跡」なので構わない。

> **字送りの補正が要る。** `transform` は組版の幅を変えないので、掛けただけでは
> 隣の字が動かず、縮めた字のうしろに隙間が空く。余り／不足を `margin-right` で
> 足し引きして詰めている（かなは全角＝1em 送りなので、半分に縮めた字は 0.5em 詰める）。
>
> 箱そのものの幅はいじっていない。未確定の字の下線や、お題のいま狙う字の枠は
> 箱に付いているので、字と同じ倍率で一緒に伸び縮みしてくれる。

#### なぜ「その字を出すのにかかった時間」ではないのか

はじめは「その面を踏みはじめてから確定するまで」を測り、それを**字の大きさ**にしていた。
これは失敗だった。**「お」は5回踏むので必ず「あ」より大きくなる**——つまり行の位置を
測っているだけで、打った人が迷ったかどうかは何も出ていなかった。

測るべきは**踏んでいない時間**のほう。こうすると、

- 1押しの字も5押しの字も、**同じ間で踏めば同じ幅**になる
- 環を回す速さを倍にしても幅は変わらない（回している時間は間隔に入らない）

Generative Gestaltung の [P_3_1_1_01](http://www.generative-gestaltung.de/2/sketches/?01_P/P_3_1_1_01)
と同じ考え方。あちらは `timeDelta = millis() - pMillis`（打鍵と打鍵の間隔）を
0〜5000ms → 文字サイズ 15〜800px に写している。こちらは足なので下限を上げ、
写す先を大きさではなく幅にした。

#### 値の決め方

`config.js` の `TIME_WIDTH`。幅の範囲は `minPct` / `maxPct`（既定 50〜150）。
`minMs` を 0 ではなく 200 にしてあるのは、
マットは面から面へ足を運ぶだけで 400ms 前後かかるため。0 を基準にすると、
普通に踏んでいるだけの字まで中くらいの幅になってしまう。

`inGame` を false にするとタイムアタックでは効かなくなる。

**最初の1字は必ず最も細い**（前の字が無いので間隔が測れない）。
幅は**踏みはじめた瞬間に決まる**ので、確定を待つあいだに変化することはない。

#### カーソル ＝ 次の字の幅

字の末尾に出るカーソルは、ただの入力位置の目印ではない。
**次の字が今踏めばどれだけの幅で出るか**を、そのままカーソルの幅で見せている。
止まっているほど伸び、`maxMs`（2500ms）で頭打ちになったら色が変わる。

```
踏んだ直後   ▬        （0.50em ＝ 最も細い）
   0.5 秒後  ▬▬▬      （0.71em）
   1.4 秒後  ▬▬▬▬▬    （1.10em）
   2.5 秒後  ▬▬▬▬▬▬▬  （1.50em・頭打ち。色が変わる）
```

幅は確定した字と**同じ関数**（`widthForMs`）から引いているので、
カーソルが出している幅と、そこで踏んで出てくる字の幅は必ず一致する。
待っているあいだ何も起きていないように見えるのを避けるための表示でもあり、
「今踏めばこの幅」が見えるので、幅を狙って踏むこともできる。

**字を回しているあいだは出さない。** 未確定の字は薄く出るので、そこに線が並ぶと
どこまでが字でどこからが次なのかが読めない。はじめは未確定の字に下線を引いて
カーソルと見分けさせようとしたが、字ごとに幅が違ううえ2本の線の高さが揃わず、
かえって目障りだった。下線をやめ、さらにカーソルも引っこめて、
**1字打ち終えてから次の溜めが見えはじめる**という順番にした。
回しているあいだは「確定まで」のメーターが減るので、待ちの手がかりは別にある。

なお、溜めは**最後に踏んだ瞬間から**数えている（確定を待つ時間も溜めに入る）ので、
カーソルは 0 からではなく、そのぶん伸びた状態で出てくる。これは正しい——
実際にその時間ぶん足が止まっているし、そこで踏んだ字はその幅で出る。

### 二人のずれ → 字の姿（二人モード）

相手と呼吸が合ったかどうかが、そのまま文字の像として残る。
見せ方は画面の「ずれの見せ方」で3つから選ぶ。いずれも
ずれ ÷ 許容ずれ（`pairMs`）の比をそのまま量に写している。

| | そろったとき | ずれたとき | 向き |
|---|---|---|---|
| **大きさ** | 大きく育つ | 縮む | そろえば得 |
| **ぼかし**（既定） | くっきり | ぼける | ずれ＝崩れ |
| **短冊** | 一直線 | ばらばらに割れる | ずれ＝崩れ |

ぼかし・短冊と大きさでは**向きが逆**。
「ずれると崩れる」は崩さないように踏む動機になり、
「そろうと育つ」は合わせにいく動機になる。
二人の身振りがどう変わるかを見たいので、両方を置いて選べるようにしてある。

**字幅**（そろうほど広く、ずれるほど細い）は別立ての入／切で、
上の3つの**どれにも重ねられる**。行の高さを崩さず、ぼかし・短冊・大きさの
どれとも取り合いにならないため、4つ目の選択肢にせず独立させてある。

#### ぼかし（既定）

既存作 [boin-shiin-mvp](../boin-shiin-mvp/) と同じ作り方。上限 0.22em もあちらの値。

```
  40ms ずれ  →  blur 0.006em（くっきり）
 700ms ずれ  →  blur 0.103em
1450ms ずれ  →  blur 0.213em（ほぼ読めない）
```

#### 短冊

字を**横に9本の短冊**へ切り、一本ずつ左右にずらす。
ずらし量は上端から下端へ進む正弦波で、**振幅が二人のずれ**。
そろっていれば一直線、ずれるほど大きく割れる。

既存作 [Sessan](../Sessan/) の `renderer.js` と同じ仕掛け。
あちらは**縦**に切って**上下**へ、振幅は心拍の脈で決めていた。
こちらは**横**に切って**左右**へ、振幅は二人のずれで決める。

```
  40ms ずれ  →  振幅 0.009em（ほぼ一直線）
 700ms ずれ  →  振幅 0.159em
1450ms ずれ  →  振幅 0.330em（ばらばらに割れる）
```

Sessan は canvas に一度刷ってから短冊で切り出していたが、こちらは canvas を持ち出さず、
**同じ字を9枚重ねて `clip-path` で一本ぶんだけ見せている**。
文字送りやテーマの色を DOM 側に任せられるので、そのほうが安く済む。

- 字送りの幅は**見えない土台**（`.slice-base`）が担い、短冊は絶対配置で重ねる。
  こうしないと、ずらすたびに行が崩れる
- 短冊の左右には**振幅ぶんの余白**を付けてある。割れた字ほど自分で隣を押しのけるので、
  大きく崩れた字が隣と重なって読めなくなることがない
- `line-height` を 1.3 に広げてあるのは、`clip-path` の箱から字がはみ出して
  上下端が切れるのを防ぐため

`config.js` の `DUO_SLICE` で本数・振幅・波の巻き数を変えられる。
`waveTurns` が 1 未満だと字全体が一方向に傾き、1 以上だとジグザグに割れる（Sessan と同じ意味）。

#### カーソル ＝ 相方が今踏めばどうなるか

二人モードにも同じ約束でカーソルを出す。ただし**向きが逆**で、
一人モードが「待つほど伸びる」のに対し、こちらは**待つほど縮む**。
ずれるほど痩せるので、相方を待たせているあいだカーソルが痩せていく——
「早く踏まないと小さくなる」が見えるようにするため。

幅は選んでいる見せ方から引く。

| 見せ方 | 待ち 0ms | 待ち 1500ms |
|---|---|---|
| 大きさ | 2.00em | 0.40em |
| 字幅のみ | 1.50em | 0.50em |
| 大きさ＋字幅 | 3.00em | 0.20em |
| ぼかし・短冊（幅が変わらない） | 1.00em | 1.00em |

ぼかし・短冊だけのときは字の幅が変わらないので、カーソルもただの目印として素の 1em で出る。

#### 大きさ

**そろうほど大きい。** ぴたりと合えば 2.0 倍まで育ち、許容いっぱいまでずれると 0.4 倍まで縮む。

```
   0ms ずれ  →  2.00 倍
  50ms ずれ  →  1.65 倍
 150ms ずれ  →  1.43 倍
 300ms ずれ  →  1.22 倍
 600ms ずれ  →  0.94 倍
1000ms ずれ  →  0.67 倍
1500ms ずれ  →  0.40 倍
```

一人モードの字幅（`TIME_WIDTH`）と違って**大きさ**を動かすので、行の高さは揃わなくなる。
それで構わない——二人で踏んだ跡が行の乱れとして残るほうが、この場合は良い。

##### ずれの比をそのまま写すと差が出ない

はじめは ずれ ÷ `pairMs` を**そのまま**大きさに写していた。これでは
**少しのずれと大きなずれがほとんど同じ大きさで出る**。

理由は分母。`pairMs` は 1500ms あるが、二人で狙って踏めば実際のずれは
**50〜500ms に固まる**——つまり比は 0.03〜0.33 の範囲しか使われず、
上の表でいえば「2.00 倍から 1.2 倍あたりまで」しか動いていなかった。

```
比例のまま（旧）    0ms 1.60 / 50ms 1.57 / 150ms 1.50 / 300ms 1.39 …  ← ほぼ同じ
curve 0.45（今）    0ms 2.00 / 50ms 1.65 / 150ms 1.43 / 300ms 1.22 …  ← 割れる
```

直し方は2つあって、

1. **分母を小さくする**（例：600ms を超えたら一律で最小）——
   大きくずれた字が全部同じ大きさになってしまう
2. **比を曲げる**——小さいずれのあたりを引き伸ばし、大きいずれは最小へ滑らかに寄せる

2 を採った。`DUO_SIZE.curve`（0.45）乗してから写している。
`1` にすると元の比例に戻り、小さくするほど「ぴたり合ったときだけ大きい」に寄る。
範囲は `maxEm` / `minEm`。

**ぼかし・短冊・字幅は比例のまま。** 同じ curve を掛けることもできるが、
あちらは「崩れ」なので、少しのずれで大きく崩れると字が読めなくなる。

#### 字幅（重ねる入／切）

**そろうほど広い。** 合えば 150%、ずれるほど痩せて 50% まで。既定は切。

これだけは見せ方の4つ目ではなく、**上の3つのどれにも重ねる**スイッチにしてある。
`transform: scaleX()`（一人モードと同じ仕掛け）で伸縮させるだけなので、
ぼかし・短冊・大きさのどれとも取り合いにならず、行の高さも崩さないため。

- **大きさ＋字幅** … そろった字が縦にも横にも育つ。いちばん効きが強い
- **ぼかし＋字幅** … ずれた字が細く薄くなって、そのまま消えていくように見える
- **短冊＋字幅** … 割れ幅も一緒に伸縮する（短冊は字の内側なので、倍率がそのまま乗る）

> **`margin` が短冊と取り合う。** 短冊は「割れたぶん隣を押しのける」余白を、
> 字幅は「`transform` が組版の幅を変えない」ぶんの送り補正を、どちらも `margin` に書く。
> `renderDuo` で**両方を足して1か所に書く**ようにしてある（`margin-right` ＝ 短冊の余白 ＋ 送り補正）。
>
> `em` は自分の `font-size` 基準なので、大きさを変えた字でも送りは正しく詰まる。

`config.js` の `DUO_WIDTH`（`maxPct` / `minPct`）で範囲を、
`DEFAULT_DUO_WIDTH` で既定の入／切を変えられる。

濁点を掛けても大きさ・崩れ具合は据え置き（後から姿が変わらないように）。

### マットの読み取りとキーボードの読み取りが別経路なわけ

Gamepad API には「押された」というイベントが無く、毎フレーム読みに行くしかない。
一方キーボードは押した瞬間にイベントが来る。

最初は両方を毎フレームの走査にまとめていたが、これだと
**1フレーム（約16ms）より短い打鍵が丸ごと落ちる**。
マットは接触が 100ms 以上あるので取りこぼさないが、指はそこまで待ってくれない。
そこでキーボードだけはイベントで直にエッジを立て、溜め・デバウンス・同時踏み判定の手前
（`#edgeDown` / `#edgeUp`）で合流させている。以降の扱いはマットとまったく同じ。

なお `holdMs` が入ってからは、踏んだ瞬間に入力が出ることはもう無い。
それでもエッジを取りこぼすと溜めが始まらないので、この分岐は要る。

## キーボード代替

マットが手元に無くても全機能を試せる。反転盤面の3×3をそのまま指の位置に写してある。

**画面の盤面と同じ並び**を指に写してある。画面を見ながら押せば迷わない。

```
子音マット（スロット0）            母音マット（スロット1）
q w e  =  あ  か  さ               u i o  =  あ い う
a s d  =  た （休）な              j   l  =  え    お
z x c  =  は  ま  や

s は中央＝home。**s を2回**で濁点
2 = ら行（START）   1 = わ行（SELECT）   1+2 同時 = 削除
```

母音側のキーは二人モードでしか効かない（他のモードでは `slotCount` が 1 なので無視される）。

> 以前は**マット裏面の並び**（q w e = ら や ま）に対応していて、画面と上下左右が逆だった。
> 母音マットを反転させたときに揃えて、両方とも画面どおりに直してある。

展示のときは誤爆するので、画面下の調整パネルから切っておく。

## マットの仕様
