# AtomPrinter

M5Stack ATOM Printer（ATOM Lite ＋ 58mm 感熱プリンタ）で、**日本語の文字と画像**を刷るための一式。

プリンタ本体の文字は ASCII しか出ないので、日本語も画像も **Mac 側で 384 ドット幅の白黒画像にしてから送る**。
ATOM はその画像を受け取ってプリンタに流すだけ。

| 置き場所 | 中身 |
|---|---|
| `PRINTER_FW/` | ATOM に焼くファーム。公式 [m5stack/ATOM-PRINTER](https://github.com/m5stack/ATOM-PRINTER)（`aa35436`, 2025-04-08）の `examples/PRINTER_FW` に `src/` を同梱し、画像まわりを直したもの |
| `studio/` | Mac のブラウザで開く GUI。文字と画像を白黒にして、プレビューを見ながら刷る |
| `LICENSE` | 公式リポジトリの MIT ライセンス |

## 使い方

1. プリンタに 12V をつなぐ
2. Mac の Wi-Fi で `ATOM-PRINTER_xxxx` につなぐ（パスワードなし。xxxx は機体ごと、手元の機体は `D7ED`）
3. `studio/` をブラウザで開く。Claude Code からは launch 設定 `atomprinter`（http://localhost:8989）
4. 文字か画像を作って「印刷」

ATOM の Wi-Fi につないでいる間、Mac はインターネットに出られない。

公式の印刷ページ（ASCII / QR / バーコード）は今までどおり `192.168.4.1` で開ける。

## studio でできること

- **文字**：書体（Mac に入っている書体名なら何でも）、太さ、大きさ、行送り、字間、余白、揃え、白抜き。
  1文字ずつ測って幅 384 ドットで折り返す。文字はディザをかけずにしきい値で切る（かけると輪郭がざらつく）
- **画像**：ドロップ／選択／⌘V 貼り付け。幅、回転、明るさ、コントラスト、反転。
  白黒の作り方は 誤差拡散（Floyd–Steinberg / Atkinson）、網点（Bayer）、しきい値 の4つ
- プレビューは 1 ドット = 1 ピクセルの実寸。紙の長さと送信時間の目安が出る
- 紙送りボタン

`studio/js/printer.js` は UI から切り離してあるので、他の作品からも
`AtomPrinter.printCanvas('192.168.4.1', canvas)` で刷れる（canvas は幅 384 以下・8 の倍数・白黒）。

## ファームに入れた変更

公式のままだと画像がまともに刷れないので、4点だけ直した。変更箇所には `改変：` とコメントしてある。

1. **画像の左上 64 ドットが化ける。** `printBMP` が命令ヘッダを画像データの先頭 8 バイトに上書きしていた。ヘッダは別の配列で組むようにした
2. **1回の要求に2回返事していた。** アップロード完了時と本体ハンドラの両方で `send` していた。返事は `handleBMPDone` の1回だけにした。
   あわせて、容量オーバーのとき途中までのデータを刷っていたのをやめ、バイト数が幅×高さと合わないときも刷らずにエラーを返す
3. **別ページから結果が読めない。** `enableCORS(true)` を足した。studio は `localhost` から `192.168.4.1` を叩くので、これが無いと成功か失敗か分からない

4. **大きい画像が文字化けして出る。** 384×223（約10KB）を1回の画像命令（GS v 0）で送ると、プリンタが途中で画像モードを抜け、
   残りのバイトを中国語（GBK）の文字として刷った（「丂」＝0x81 0x40 が並ぶ）。4KB の公式サンプルは通る。
   `printBMP` で 24 行ずつの帯に分けて送るようにした（`BMP_BAND_ROWS`）

あわせて `/bmp_size` に `feed`（印刷後の改行数）を足した。

## つまずいたところ

- **書き込み速度。** `esp32:esp32:m5stack_atom` の既定は 1500000 で、ATOM Lite の USB 変換チップでは失敗する。**115200 にする**
  ```bash
  ~/bin/arduino-cli upload -p /dev/cu.usbserial-6D4E27CA00 --fqbn esp32:esp32:m5stack_atom:UploadSpeed=115200 PRINTER_FW
  ```
- **ポートが busy。** Arduino IDE のシリアルモニタが開いているとつかまれたままになる。IDE を閉じる
- **`libsdetect.d: No such file or directory`。** ビルドキャッシュが壊れているだけ。`--clean` を付けるか IDE を開き直す
- **`arduino-cli` が見つからない。** `~/bin/` にあって PATH に入っていない
- **AP の名前。** 公式 README の `ATOM_PRINTER-xxxx` は誤りで、実際は `ATOM-PRINTER_xxxx`
- **起動しても紙に何も出ない**のは正常。Switch Science の記事で `Mode: AP` などが刷られているのは M5Burner 版の動き
- **送信が遅い。** ATOM → プリンタが 9600bps なので、幅 384 の画像は **紙 1cm あたり約 4 秒**（384×400 ドット＝5cm で約 20 秒）。
  ファームは刷り終わってから返事をするので、その間 studio は待っている
- **一度に送れるのは 50KB（384 幅で約 1066 行 ≒ 13cm）まで。** それより長いものは printer.js が分割して送る。途中は改行を入れないので紙の上ではつながる
- **docs.m5stack.com は 2026-10 時点でつながらないことがある。** Switch Science のミラー https://docs.m5stack.switch-science.com/en/atom/atom_printer は開ける

## やらないと決めたこと

- **USB 有線での印刷。** 公式ファームの Wi-Fi 経由で足りたので、ファームにシリアルの橋渡しは足していない
- **プリンタの通信速度を 115200 に上げる。** 命令（`1B 23 23 53 42 44 52 …`）はあるが、プリンタ側に設定が残る可能性があり、戻せなくなると困るので触っていない。送信の遅さが展示で問題になったら検討する
- **縦書き。** 1文字ずつ置いているので足せるが、約物の回転と位置ずらしが要るので今回は入れていない
- **QR・バーコードを studio から刷る。** 公式ページで刷れるので重ねていない

## 本番チェックリスト
- [ ] Mac が `ATOM-PRINTER_xxxx` につながっているか（インターネットが切れるのを前提に組む）
- [ ] 12V アダプタ（2.5A 以上）と予備のロール紙（直径 37mm 以内・幅 58mm）
- [ ] 想定する長さの画像を一度刷って、送信時間が待てる長さか
- [ ] 電源を入れ直して `192.168.4.1` が開くか
- [ ] フォント：studio は Mac に入っている書体で描くので、展示用の Mac で書体名が通るか
