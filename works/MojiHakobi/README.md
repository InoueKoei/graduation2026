# 文字運び ─ 共同運搬型かな文字入力

文字をキーで打つのではなく、画面上の文字オブジェクトを掴んで運ぶことで文章を入力する。
文字には字面の黒量から出した「重さ」があり、**軽い文字は一人で運べるが、重い文字は二人が同時に掴まないと動かない。**

通常は一人で完結する文字入力に、他者との協力・「せーの」の同期・文字を運ぶ身体感覚を持ち込むための試作。

検証したいのは「**文字を運ぶという本来不要な手間を加えると、通常の文字入力では起きない二者間のやりとりが生まれるか**」。

---

## 動かし方

依存パッケージなし。Node があれば動く。

```bash
npm --prefix SourceCode/works/MojiHakobi run dev
```

フォルダの中からなら `node server.js` だけでも動く。

起動すると3つの URL が出る。

| 画面 | URL | 開く端末 |
|---|---|---|
| メイン画面 | `http://localhost:3100/` | Mac（大画面・プロジェクタ） |
| P1 コントローラ | `http://<MacのIP>:3100/c?p=1` | iPad / iPhone / PC |
| P2 コントローラ | `http://<MacのIP>:3100/c?p=2` | iPad / iPhone / PC |
| 重さ計測ツール | `http://localhost:3100/tools/measure-weights.html` | Mac |

コントローラはメイン画面と**同じ Wi-Fi** につなぐ。
接続先の URL はメイン画面の下にも出ていて、二人ともつながると自然に消える。

### 端末構成について

要件書8〜10章のうち **B案（複数デバイス）** を採った。
macOS は複数のマウスを1つのシステムカーソルに統合してしまい、ブラウザから P1 / P2 を分離できない。
検証したいのは「二人が独立した入力で同じ文字を共同運搬する体験」であって1台で完結することではないので、
確実に二人分の入力が取れるこちらを選んでいる。

**iPad は横向き**で使う。コントローラはメイン画面と同じ縦横比の枠を描くので、
縦向きだと枠が画面の中央に細長く収まってしまい、扱いにくい。

iPad の自動ロックは「なし」にしておく。画面が消えると接続が切れる（復帰すれば自動でつなぎ直す）。

## 操作

コントローラは**メイン画面の縮小地図**になっている。触った場所がそのままメイン画面上のカーソル位置になる。

| 動作 | 結果 |
|---|---|
| 指を置く | その場所にある文字を掴もうとする |
| ずらす | 掴めていれば運ぶ |
| 指を離す | その場に落とす |

掴むための専用ボタンは置いていない。**二人が同時に手を伸ばす動作そのものを「せーの」にしたい**ため。

- 軽い文字は一人で運べる。
- 重い文字は一人だと動かない。数pxだけついてきて、わずかに震える。「もう一人必要」という説明は出さない。
- 二人が同時に掴むと運べるようになる。文字は**二人のカーソルの中点**で動く。
- 運搬中に片方が離すと、文字はその場で止まる。残った一人だけでは動かせない。
- 置き場の文字は何度使っても消えない。
- 置き場の上で離すと文字は消える（運び間違いを「戻す」動作）。

### 濁点・半濁点

「が」のような完成した一文字は用意していない。「か」を運び、別に「゛」を運んで右上に置くと「が」になる。

- 濁点がつけられない組み合わせ（「ぬ」＋「゜」など）はスナップせず、落とした場所にそのまま残る。
- どの文字にもスナップさせたいときは `public/config.js` の `dakuten.strict` を `false` にする。

### 組版

**落とした場所にそのまま置かれる。** 行への整列はしない。
上下のズレも字間のばらつきも、二人で運んだ痕跡としてそのまま残る。

記録用の「読み」だけは、y が近いものを同じ行とみなして x 順に読み直している（`readText()`）。画面上の配置には影響しない。

## メイン画面のキー操作（操作者用・観客には見せない）

| キー | 動作 |
|---|---|
| `d` | 状態表示の切り替え（threshold / 接続 / 読み など） |
| `[` `]` | threshold を 0.05 ずつ増減。何文字が二人がかりになるかが変わる |
| `c` | 入力エリアを空にする |
| `n` | 新しいセッションを始める（ログファイルが変わる） |
| `1` | 開発用：マウスで P1 を操作 |
| `2` | 開発用：矢印キー＋Enter で P2 を操作 |

`1` `2` は一人で挙動を確かめるための仮の入力。展示では使わない。

## 重さ

### 算出

字面（仮想ボディ）に占める黒の量を数え、**五十音46文字の最小を 0、最大を 1** として正規化した値。
要件書5章のとおり計測はアプリの外側でおこない、アプリには `data/weights.json` を渡すだけにしてある。

ヒラギノ角ゴシック W3（`font-weight: 400`）での結果：

| | 文字 |
|---|---|
| 軽い | く へ し い こ つ て と … |
| 重い | … ね あ ほ ぬ |

`threshold 0.5` で **26 / 48 文字**が二人がかりになる。

「゛」「゜」は正規化の基準から外している。印は他のかなの半分以下しか黒がなく、
これを最小値にすると五十音が上半分に固まって、ほとんどの文字が二人がかりになってしまうため。
印自体は五十音と同じ物差しに載せた結果、下限の 0 に丸めている（＝常に一人で運べる）。

### 書体を変えるとき

**書体を変えたら必ず計測しなおす。** 黒量は書体とウェイトで変わるので、
`weights.json` と実際の表示がずれると重さの根拠が崩れる。

1. `public/config.js` の `fontFamily` と `fontWeight` を変える
2. `http://localhost:3100/tools/measure-weights.html` を開いて「計測する」
3. 「data/weights.json に保存」
4. メイン画面を再読み込み

計測ツールは、指定した書体が実際に入っているかも確かめる。
かなはどの書体でも1em幅なので `measureText` の幅では判別できず、`document.fonts.check()` は
代替書体で描けるだけで `true` を返してしまうため、**「あ」を描いた絵そのものを既定書体と見比べて**判定している。

> ヒラギノ角ゴシックの CSS 書体名は `"Hiragino Sans"` のひとつだけ。
> 「ヒラギノ角ゴシック W3」「Hiragino Sans W3」という書体名は存在せず、W0〜W9 は `font-weight` で選ぶ。

## 研究用ログ

`logs/session-<日時>.jsonl` に1行1イベントで貯まる。`n` キーで新しいファイルに変わる。

| イベント | 中身 |
|---|---|
| `grab` | 誰が・どの文字を・重さいくつで掴んだか |
| **`co_grab`** | **二人が同じ文字を掴んだ。`gapMs` が二人の時間差** |
| `release` | 誰が離したか、何ms掴んでいたか、残りの持ち手 |
| `drop` | 落とした位置、運搬時間、途中で離した回数、その時点の文字列 |
| `snap` | 濁点がついた（`composed` に「が」などの合成結果） |
| `remove` | 文字が消えた理由 |
| `trace` | 二人の位置と掴んでいる文字（既定 20Hz） |
| `threshold_change` | 操作者が threshold を変えた |

要件書14章の「二人が同じ文字を掴むまでの時間差」は `co_grab.gapMs`。
同期度・「せーの」のタイミング・ペアごとの差の分析はここから始められる。

軌跡を残したくない、あるいはファイルを軽くしたいときは `config.js` の `log.traceHz` を下げる（`0` で軌跡なし）。

## 調整できるところ

ユーザーテスト中に触るのはほぼ `public/config.js` だけ。

| 値 | 意味 |
|---|---|
| `threshold` | これ以上の重さは二人がかり |
| `heavy.pullMax` / `tremorAmp` | 一人で掴んだときの「動かないが反応はする」加減 |
| `dakuten.snapRadius` / `strict` | 濁点のスナップ範囲と、無効な組み合わせを許すか |
| `controller.showPalette` | 手元に置き場を薄く出すか。**相手や画面を見るかを厳しく観察したいときは `false`** |
| `controller.showStuck` | 「重くて動かない」を手元にも出すか。既定は `false` |
| `drop.removeOnPalette` | 置き場に戻して消せるようにするか |

`controller.showStuck` を既定で `false` にしているのは、手元だけで重さが分かってしまうと
メイン画面や相手を見なくなり、いちばん観察したい行動が消えてしまうため。
重さへの気づきはメイン画面の反応に任せている。

ブラウザのコンソールからも触れる。

```js
mojiHakobi.threshold = 0.35
mojiHakobi.readText()
mojiHakobi.setPointer('p1', 458, 189, true)   // 決まった手順を再現したいとき
```

## 構成

```
server.js                     中継と記録だけ。文字のロジックは持たない
public/
  index.html / main.js        メイン画面。掴む・運ぶ・落とす・濁点スナップ
  controller.html / .js       P1 / P2 の手元。絶対マッピングのタッチパッド
  config.js                   調整値
  kana.js                     五十音・濁点の対応表
  net.js                      WebSocket（切れたら自動でつなぎ直す）
data/weights.json             計測済みの重さ
tools/measure-weights.html    黒量の計測ツール（アプリ外）
logs/                         セッションごとの研究ログ
```

WebSocket は依存パッケージを足さずに済ませるため、RFC 6455 のうち必要な部分だけを `server.js` に手書きしてある。
座標を毎フレーム送るので HTTP では間に合わないが、この用途では扱うのがテキストフレームだけなので短く収まる。

## 今回やっていないこと

要件書15章のとおり、Variable Font・動的なウェイト変更・3D・物理演算・重力・慣性・衝突・文字の回転・
二人の力加減による字形変形・スコア・制限時間は入れていない。

まず「重い文字を二人で運ぶだけで、通常の文字入力にはない行動が起きるか」を確かめる。

小書き文字（ゃゅょっ）・長音符・句読点・漢字も入れていない。必要になった段階で `kana.js` に足す。

## つながらないとき

まず `http://<MacのIP>:3100/api/peers` を、つながらない端末のブラウザで開く。
サーバーから見て誰が接続しているかがそのまま出る。

```json
{ "接続中": { "main": true, "p1": true, "p2": false } }
```

- **このページ自体が開けない** → ネットワークの問題。同じ Wi-Fi か、Mac のファイアウォールを確認する。
- **開けるのに `p2: false` のまま** → WebSocket だけが通っていない。コントローラ画面の下に赤い字で理由が出ているはず。

### 「別の端末が P2 になった」と出る

**同じ `?p=2` を2箇所で開いている。** iPad の Safari と Chrome の両方で開いたまま、というのがよくある。
役割はひとつの端末しか持てないので、後から開いたほうが勝ち、前のほうはこの表示になって止まる。

使わないほうのタブを閉じてから、使うほうを再読み込みする。

> 以前は、切られた側が黙って繋ぎ直していたため、2つのタブが役割を延々と奪い合って
> **どちらも接続できない**状態になっていた。いまは切られた側が引き下がり、理由を画面に出す。

### 途中で切れる

iPad の自動ロックを「なし」にする。画面が消えると接続も切れる。
（HTTP 配信なので Wake Lock API が使えず、ブラウザ側からは画面を起こしておけない。）

切れても復帰すれば自動でつなぎ直す。掴んだまま切れた場合は、その文字は自動的に手放される。

## 分かっている制約

- メイン画面のタブを裏に回すと、ブラウザが描画を止めるので文字も止まる。展示中は前面に出したままにする。
- 画面ロックのない環境が前提。iPad の自動ロックは切っておく。
- HTTP（非 TLS）で配信しているため、画面のスリープを止める Wake Lock API は使えない。端末側の設定で対応する。
