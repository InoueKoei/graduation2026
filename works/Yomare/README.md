# Yomare — 読まれ字

白い面の上に、タイポスの12エレメントを3Dプリントした部品を置いてひらがなを組む。
真上のカメラが配置の静止を見届けたら、**切り出しただけの画像**を macOS 標準の OCR（Vision）に読ませる。

- 読めなければ、何もしない
- 読めたら、部品のまわりに光が出る
- そのまま置かれ続けたら、組んだ形が中央へ移り、読まれた字を小さな見出しにして、それまでの字と寄り集まって塊になる
- 特定の語が読めたら、絵文字が流れる

**学習も補正もしない。** 制約は「日本語として読め」の一つだけ。

> 合否の基準：**組んだ部品が読まれたときだけ光り、読まれた字の下に、その形がそのまま残るか。**

## 流れ

```
置く ─→ 動いている ─→ 静止 1.0秒 ─→ 切り出して OCR（配置ごとに1回だけ）
                                      │
                         読めず ←─────┤ 何もしない。動かせばまた読む
                                      │
                         読めた ←─────┘ 光る（保持するほど強くなる）＋ 6語なら絵文字
                                      │
                       3.0秒保持 ─→ 形が中央へ移り、塊に加わる
```

途中で動かしたら最初から。読んでいる最中に動かされた読みは捨てる。

この流れは**まとまり（1語）ごと**に別々に進む。テーブルを囲んで何人かが同時に組んでも、
それぞれの語が自分のペースで読まれ、光り、中央へ寄って残る。

## 構成

```
[白い面]  寝かせたモニタ or プロジェクター。surface.html を全画面で出す
    ↑ 部品を置く
[カメラ]  真上から（Continuity Camera / USB）
    ↓
操作画面 control.html（ノートPC側の画面）
    カメラ → 四隅で白い面の座標に写す → 二値化と連結成分 → 静止したか
    静止したら、カメラ映像を矩形で切り出して POST /ocr
    ↓                                       ↑
ocr_server.swift ── Vision（ja-JP、言語補正なし）が読む
    ↓
BroadcastChannel で白い面へ出来事だけを送る（read / clear / fix / emoji）
```

Python は使っていない。Web 側は素の HTML/JS（ビルド不要・ライブラリなし）、
OCR だけを Swift の1ファイルにした。**Vision はブラウザから呼べない**ので、そこだけ外に出している。
Swift のサーバはページの配信も兼ねるので、立てるものは1つだけ。

| ファイル | 持っているもの |
|---|---|
| `ocr_server.swift` | ページの配信と `POST /ocr`。受けた画像を何も加工せず Vision に渡す。読みと一緒に、各行の四隅（字の向きのまま）を返す |
| `run.sh` | 必要ならビルドして起動する |
| `web/common.js` | 両ページの決まりごと。置く場（外周の帯）・集まる場（中央の円）・時間・既定値 |
| `web/emoji.js` | **絵文字の設定。** 語と絵文字の対応、流れる時間、同じ語を流さない間、粒の数と大きさ。ここだけ書き換えて両ページを再読み込みすれば変わる |
| `web/control.html` `control.js` | 操作画面。カメラ・四隅合わせ・閾値・検出・状態・OCR への受け渡し |
| `web/surface.html` `surface.js` | 白い面（正方形）。光・中央の塊・絵文字。カメラも OCR も知らない |

## 動かし方

```bash
cd SourceCode/works/Yomare
./run.sh                  # 初回だけビルドが走る（十数秒）
```

`Vision の準備ができた` と出たら：

1. **http://localhost:8765/** を Chrome で開く（操作画面）。カメラの許可を出す
2. 「白い面を開く」→ 出たウィンドウを白い面のディスプレイへ移し、クリックで全画面
3. 「四隅を合わせる」→ 白い面に 1〜4 の角が出る。操作画面のカメラ映像で、
   赤い丸 1〜4 を同じ番号の角にドラッグして重ねる。もう一度押して終える
4. 部品を1つ置き、「閾値」の黒い線を**2つの山のあいだ**にドラッグする（「自動で決める」から始めてもよい）
5. 「見えているもの」で、部品が赤く塗られていれば準備完了

設定（四隅・閾値・明るさ・光の色・カメラ・映像の向き）はブラウザに覚えさせてあるので、次回は 1〜2 だけでよい。

**2つのウィンドウはどちらも隠さないこと。** ブラウザは見えていないタブの描画ループを止めるので、
操作画面を最小化したり別タブの裏に回したりすると、検出が止まる。
ノートPCの画面に操作画面、白い面のディスプレイに白い面、と分けて置けば問題ない。

## 操作画面

| 場所 | 何をするか |
|---|---|
| カメラ | 赤い丸 1〜4 をドラッグして白い面（正方形）の四隅に重ねる。点線の四角と円のあいだが置く場 |
| 映像 0°／90°／180°／270° | 上の段。カメラ映像を時計回りに回す。カメラを横向きや逆さに据えたとき、映像を白い面と同じ向きにする。合わせ済みの四隅は一緒に回るので、合わせ直さなくてよい |
| 見えているもの | 白い面の向きに直した、機械に見えている絵。**赤＝部品、青＝小さいので無視、橙＝縁に触れたので無視、灰＝5秒動かないので無視**。点線の枠が1語として読むまとまり |
| 状態 | まとまりが2つ以上あると、まとまりごとの状態（静止を待っている／読めた「…」／残した「…」）が並ぶ |
| 閾値 | ヒストグラムの黒い線をドラッグ。赤い側が部品とみなされる。青い印は大津の自動値 |
| 部品は地より暗い／明るい | 押すと反転。暗い布に明るい部品を置くならこちら |
| 小さい塊を無視する | 置く場の面積に対する割合（0.001〜1%、対数の目盛り）。横に何画素未満を捨てているかが出る。ゴミが青く出ているなら上げ、てん などの部品が青くなっているなら下げる |
| まとまりとみなす間隔 | 部品どうしがこれより近ければ1語（正方形の一辺に対する割合、既定 10%）。1語が割れるなら上げ、隣の語とくっつくなら下げる |
| 白い面の明るさ | プロジェクターで部品が光に洗われるなら下げる |
| 中央の円 | 集まる場の半径。動かしているあいだ白い面に輪郭が濃く出る。検出の範囲も同時に変わる。**小さくすると、入りきらない古い字は消え、大きくし直しても戻らない** |
| 読めた合図の光 | 色。**光が「見えているもの」で赤く拾われたら、色を明るくするか閾値を下げる** |
| 読ませたもの | OCR に渡した画像そのものと、読みの記録 |
| 残したものを消す | 中央の塊を空にする |
| 残した字 — PNG に書き出す | 残した字の一覧。「PNG」で1つ、「全部書き出す」でまとめて保存する。地は透明、字は読んだ向きに起こしてある。ファイル名は `語_月日時分秒.png`（残した時刻。例 `よい_1103135346.png`）。画面を開き直すと一覧は消える |

閾値を数字の入力にしなかったのは、**「2つの山のあいだに線を置く」が目で見て分かる**から。
地と部品の平均と、部品とみなした面積の割合も下に出る（部品の側が 30% を超えたら、線が地の山に食い込んでいる）。

## 設計判断

### OCR に渡すのは切り出しただけの画像

二値化した画像でも、白い面の向きに写し直した画像でもなく、**カメラ映像を矩形で切り抜いたもの**。
輪郭（二値化と連結成分）は「静止したか」「どこにあるか」を知るためだけに使う。

だから**カメラは白い面に対してまっすぐ据える**。カメラが傾いていれば、OCR にも傾いた字が渡る。
回して試すことはしない。

ただし据え方の向きだけは 90° 単位で直せる（操作画面の「映像 0°〜270°」）。三脚やアームの都合でカメラを横向きや逆さに
付けても、映像を白い面と同じ向きに回してから四隅合わせ・検出・切り出しをする。これは字ごとに回して読み直すことではなく、
カメラの付け方を一度だけ直す設定。OCR に渡るのは、回した映像を矩形で切り抜いたもので、ほかの手は加えない。
向きを変えると、合わせ済みの四隅も同じだけ回す（時計回りに 90° で、映像の (x, y) が (1 − y, x) へ移る）。

### 「日本語」以外の制約を置かない

Vision に指定しているのは `recognitionLanguages = ["ja-JP"]` だけ。

- `usesLanguageCorrection = false`。辞書で語らしく直すのは補正にあたるので切った
- ひらがな・カタカナ・漢字・数字、返ってきたものはそのまま見出しになる。仮名に絞らない
- 確信度で足切りしない。空でなければ「読めた」
- 形の照合で代わりに読む経路は持たない

手元の確認（フォントで描いた字をそのまま渡した場合）：

| 渡したもの | 返ってきたもの |
|---|---|
| うし | うし（確信度 1.00） |
| つ | **（読めず）** |
| 木 | 木（0.50） |
| 12 | 12（0.50） |

**1字の「つ」は、フォントそのままでも読まれない。** Vision は横書きの「行」を探す設計なので、
単純な1字は行として拾われにくい。ここを直すと補正になるので、そのままにしてある。
どの字が読まれ、どの字が読まれないかは、この装置が出す結果の一部。

### 残すのは、読まれた瞬間の形

読ませる瞬間に、同じフレームから2つを取る。OCR へ渡す切り出しと、白い面へ残す形。
残す形は、元の解像度の映像を白い面の向きに写し直して二値にしたもので、中央へ移るときにそのまま縮む。

最初は「部品」と判定された塊だけで形を作っていたら、**「うし」の「う」の点が落ちて「つし」が残った**。
点は小さいので、ゴミ取りのふるいに掛かっていた。OCR には点ごと写った切り出しが渡っているので
「うし」と読めるのに、残る形は「つし」。読みと形が食い違う。

一度は「部品の外接矩形の内側にある小さい塊も形に含める」で直したが、これだと**ゴミの粒まで一緒に
中央へ飛んだ**。小さい塊のスライダーを対数の目盛りにして細かく合わせられるようにしたので、この手当ては外した。
いまは**「見えているもの」で赤い塊（部品）だけ**が光り、残り、飛ぶ。てん が青く（小さいので無視）なっているなら、
スライダーを下げて赤くする。既定値は 0.05%。

白い面が飛ばす前に部品を切り分けるときも、同じ基準を使う。操作画面が、スライダーの値をこの形の画素の大きさに
換算して渡し（`minPx`）、白い面はその 7割未満の粒を捨てる（細かい解像度で二値にし直しているぶん、部品が少し痩せるため）。

ただし **OCR へは生の切り出しを渡す**ので、部品のすぐそばにある小さい粒は画像に写り、読みに混ざりうる
（合成映像で、字に接した粒が句点になり「うし.」と読まれた）。

### 腕は縁で落とす

置く場の縁に触れている塊は捨てる。部品を置きに来た腕は必ず縁から入ってくるので、
腕と、腕に掴まれている部品はまとめて無視される。手を離した瞬間に部品だけが現れる。

「縁」は2つある。正方形の縁（から INSET だけ内側）と、中央の円の縁（半径 + 0.025）。
どちらも検出の格子では「見ない画素」なので、そこに接した塊は同じように捨てる。
円の上に身を乗り出した腕や、円からはみ出した塊の字が部品に化けないのも、これで済んでいる。

腕が一瞬かぶって元に戻ったときに、同じ形をもう一度読んで二重に残さないよう、
**残した配置を場所ごとに覚えておき（最近の 20）、同じ配置が現れたら読まない**。記憶が消えるのは次の節のとおり、
その場所から物が本当になくなって2秒たったとき。片付けて同じ字を組み直せば、また残る。

### 5秒動かない塊は無視する

布の柄や汚れ、残したあと片付けていない字のように、**5秒変わらない塊は「動かないので無視」**にする
（「見えているもの」で灰色）。塊は外接矩形の重なり（IoU 0.5 以上、面積の比 0.6〜1.67）で追いかけるので、
少し揺れても同じ塊とみなす。0.5秒見えなければ「どけた」とみなす。

時間だけで決めると、組んでいる途中の字まで消える。そこで例外を2つ置いている。

- **近くで部品が現れた・消えたら、まわりの塊の時計を最初から数え直す**（外接矩形の隙間が正方形の 8% 以内）。
  考えながら1つずつ組み足しているあいだに、先に置いた部品が消えない。
  小さい塊（ゴミ）の明滅では数え直さない
- **静止を待つ・読ませている・読めて保持しているまとまりの近くでは時計を止める。** 読めてから残るまで約6秒かかるので、
  止めないと残す前に部品が消える。止めるのはそのまとまりの近く（外接矩形の隙間が、まとまりとみなす間隔以内）だけなので、
  ほかの人が組んでいるあいだも、離れた柄や汚れは無視されていく

残した字は、残してから5秒で動かない塊になり、状態は「何も置かれていない」に戻る。そのまま別の場所に
次の字を組める。同じ字をもう一度残さないための記憶は、**残した場所から物が本当になくなって2秒たったとき**に消す
（「何も置かれていない」では判断しない。動かない塊として無視されていても、物はまだそこにある）。

合成映像で確かめたこと：汚れは一度だけ読ませて「読めず」になり、その5秒後に無視された。「うし」は残して5秒後に無視され、
下の帯に置いた「なつ」は「うし」と混ざらずに読まれた。無視されていた縦棒は、近くに部品を足すと戻って一緒に読まれ、
遠くに足したときは戻らなかった。

**弱いところ：** 手が字の上を横切ると、隠れた部品は一度「どけた」になり、手が離れたあと新しい塊として現れる。
二重に残さない記憶はいまは場所ごとに最近の 20 を持つので、残した字の上を手が横切っても、記憶と同じ配置なら
読み直さずに「残した」に戻るはず（実機ではまだ確かめていない）。

### 瞬間の値で状態を切り替えない

検出は閾値の際でちらつく。「動いた」「全部どけた」はどちらも、**0.35秒続いたときだけ**認める。
比べる相手は直前のフレームではなく、静止を待ち始めた時点の配置。失った画素が 30%、
新しく増えた画素が 15%、面積の差が 40% を超えたら「動いた」とする。
増えた画素は、元の配置を少し膨らませた範囲の外だけを数えるので、縁のちらつきや光の滲みでは動かない。

### 絵文字が流れているあいだはカメラを見ない

絵文字は置く場の上を流れるので、部品と取り違えうる。流れている 2.6秒は検出を止める（時間は進むので、
残すまでの保持は止まらない）。同じ語は 8秒たつまで流さない。

```
うし → 🐄    なし → 🍐    なつ → 🌻
あい → ❤️    くり → 🌰    よい → 👍
```

完全一致のときだけ流す。対応表と流れ方は `web/emoji.js` にまとめてある。1つの語に `['🐄', '🐮']` のように複数並べると、流れる1粒ずつがその中から選ばれる。

### 正方形の外周に置き、中央に集まる

白い面は正方形で、窓の中央に描く（外側は黒＝プロジェクターでは何も投げない）。

```
┌──────────────────┐
│  置く場（外周の帯）  │
│     ╭──────╮     │
│     │ 集まる場 │     │   円の半径は既定 0.27（0.12〜0.38 で変えられる）。カメラは半径 + 0.025 より内側を見ない
│     ╰──────╯     │
│                  │
└──────────────────┘
```

残した形は、部品（つながった塊）ごとに切り分けてから動かす。部品はそれぞれ違う遅れ（0〜0.4秒）、
違う速さ（0.9〜1.5秒）、横へふくらむ違う道筋で、**向きを変えずに**中央へ向かい、着いたところで
置かれていたときの配置に組み直って字になる。字の長辺は正方形の 5〜10%（もとの大きさの 45%）。
見出しは字を**読んだ向き**に回して出す（次の節）。

塊の中では、字ごとに円で近似して押し合い、重ならずに寄り集まる。部品が飛んでいるあいだも、
塊の中では着いたあとの大きさで場所を取っておく。ごく弱く揺らしてあるので、塊は止まりきらずに少しずつ動き続ける。
見出しは各字の上に 12px で出る。

塊は円の内側に留める。円の面積の 62% が埋まったら古いものから 1.5秒かけて消える
（字の大きさによるが、だいたい 16〜18個で入れ替わりが始まる）。**塊が円からあふれると、
カメラの見る帯に暗い字がはみ出して部品と取り違える**ので、上限はそのためにある。
同じ理由で、部品が帯を横切って中央へ向かうあいだ（いちばん遅い部品が着くまでの 2.2秒）は、**その道筋だけ**検出を止める（次の節）。

一番外の端は、22語を続けて加えたときで中心から 0.260 だった（カメラが見始めるのは 0.295）。

### テーブルを囲んで組む — まとまりごとに読む

置く場の部品を一度にまとめて読ませると、離れた場所で別々に組んだ語が1枚の切り出しに入り、
「よい」と「くやしい」が「よハくやしい」のように混ざって読まれた。

いまは、部品を「間隔の半分」ずつ膨らませ、つながったものを**ひとまとまり（1語）**とみなす。
まとまりごとに静止を待ち、別々に切り出して読ませ、別々に光らせ、別々に中央へ飛ばして残す。
前のフレームのまとまりとは、読ませた瞬間の配置を少し膨らませた範囲と重なるかで対応づける。
割れた・隣とくっついた・形が変わった、のどれも「動かした」として扱い、そのまとまりだけ最初から。
ほかのまとまりは止まらない。

- **間隔は見た目どおりの距離で測る。** 膨らませた範囲は中央の円の上を通ってもよい。
  置く場（帯）の中だけでつなぐと、円をはさんで向かい合う部品の近さが、帯を回り込む道のりで測られてしまう
- **まとまりに入るのは部品（赤）だけ。** 小さい塊も、5秒動かない塊も入れない。残した字は5秒で動かない塊になるので、
  そのすぐ横に次の語を組んでも、残した字とはつながらない
- **部品が中央へ飛んでいくあいだ、止めるのはその道筋だけ。** 道筋は、まとまりの枠と円の中心を両方含む矩形に、
  横へのふくらみ（最大 0.08）のぶんとして正方形の 10% の余裕を足したもの。ここに重なるまとまりだけ判定を待たせ、
  新しいまとまりとしても、動かない塊の記録としても拾わない。
  もとは検出全体を止めていたが、それだと誰かの語が残るたびに、ほかの人の語の静止の判定まで止まる
- **絵文字が流れるあいだは、これまでどおり全体を止める。** 絵文字は白い面の全体を流れるため
- OCR のサーバは1つずつ読む。2つのまとまりが同時に静止したら、片方は前の読みを待つ（数百 ms）

**向きは回さない。** 向かいや横の席から組んだ語は、カメラから見ると逆さや横倒しになる。
それでも Vision はそのまま読む（フォントで描いた字を回して渡した確認）：

| 渡したもの | 0° | 90° | 180° | 270° |
|---|---|---|---|---|
| よい | よい | よい | よい | **（読めず）** |
| くやしい | くやしい | くやしい | くやしい | くやしい |

短い語が向きによって読まれないことがあるのは、「つ」が1字では読まれないのと同じく、装置が出す結果の一部。

### 見出しは読んだ向きに出す

逆さや横向きに組まれた字は、塊の中でもその向きのまま並ぶ（部品は向きを変えずに飛ぶ）。見出しだけ正位置だと、
字と見出しが別の方向を向いてしまう。そこで見出しを、その字を読んだ向きに回し、その向きから見て字の上に置く。
向かいの席から組んだ「よい」なら、見出しも逆さで、こちらから見て字の下に出る。

向きは Vision から取る。`VNRecognizedTextObservation` の四隅は字の向きのまま返る（逆さに読んだ行は、
「左上」が画像の右下に来る）。いちばん長い行の左下→右下（ベースライン）を、切り出しの位置とカメラの四隅合わせを
逆にたどって白い面の座標へ写し、**90° 単位に丸める**。フォントで描いた字を 0／90／180／270° に回して渡すと、
ベースラインの向きはそれぞれ 0／90／±180／−90° で返った。15° 傾けたときは 14° だったり 0° だったりと揃わないので、
テーブルの四辺に丸めることにした。

画像を回して読み直しているわけではない。Vision が読むときに出した向きを、見出しの描き方に使うだけ。

### 残した字を PNG に書き出す

バナーなどに使うため、残した字を操作画面から PNG で保存できる。中身は白い面へ送った形と同じで、
読まれた瞬間の映像を白い面の向きに写し直して二値にしたもの。地は透明、色は残した形と同じ（`ink`）。
向かいや横から組んだ字も一枚の素材として使えるよう、読んだ向きの逆に回して起こし、まわりに 4% の余白を足す。

大きさはカメラ次第で、合成映像（白い面が 600px に写る）では「くやしい」が 428×125px だった。
残す形は長辺 720px を上限に作っているので、それより大きくはならない。

### 方眼やガイドは出さない

白い面には、読めた合図の光と、中央の塊と、集まる場の輪郭（ごく薄い円）しか出さない。
置き方を誘導するものを出すと、機械が読む前に人が自分で揃えてしまう。

## 確かめたこと・まだのこと

カメラの代わりに、傾けた白い紙の上に字を描いた合成映像をブラウザへ流して通した。

| 場面 | 結果 |
|---|---|
| 「うし」を置く | 1.2秒で読めた（確信度 1.00）→ 光・🐄 → 3秒後に残った（このときは端の列。中央の塊に変える前） |
| 棒を2本置く | 「読めず」。光も残す動きも出ない |
| 「くり」を読ませている最中に動かす | その読みは捨てられ、置き直した場所で読み直して残った |
| 「う」の点 | 修正後、残る形に入った |

2026-10-18 に実機でも通った。EMEET SmartCam C60E 4K を真上に据え、床に敷いた白い面で
「ける」（確信度 1.00、1965ms）と「はし」（0.50、1532ms）が読まれて残った。
閾値は 128（自動の値 127）、地の平均 205・部品の側の平均 50 で、2つの山ははっきり分かれた。

2026-10-19 に正方形と中央の塊へ変えた。塊の動きは白い面だけで確かめた（時計を差し替えて
フレームを手で進め、22語を続けて加えた）。**カメラ側で中央の円を外した検出は、実機ではまだ通していない。**
正方形に変えたので、四隅合わせはやり直しが要る。

2026-11-03 に、まとまりごとに読む処理を、部品ごとに飛ぶ・5秒動かない塊を無視する版へ合わせた。合成映像（正方形の白い面を
真上から見た絵。白い面の表示そのものは映らない）で、白い面のページも同時に動かして通した：

| 場面 | 結果 |
|---|---|
| 正位置の「くやしい」と、逆さの「よい」を上下の帯に置く | 2つのまとまりに分かれ、別々に読めて（「くやしい」0.50、「よい」1.00 と 👍）、別々に残った |
| 残して5秒たってから、「よい」だけを下の帯の中で横へずらす | 2語とも「動かないので無視」になったあと、ずらした「よい」だけ読み直して残った。「くやしい」は無視されたまま |
| 「よい」を置いたまま、「くやしい」を横倒しにして左の帯へ移す（11-02、合わせる前の版） | 「くやしい」だけ読み直して（1.00）残った。「よい」はそのまま |
| 片付けて、「くやしい」と横倒しの「あめ」を同時に置く | 白い面に光が2つ同時に出て、それぞれ部品ごとに中央へ飛び、先に残した字と塊になった |

見出しの向きと PNG の書き出しも合成映像で確かめた。正位置の「くやしい」、右へ倒した「なし」、左へ倒した「あめ」、逆さの「よい」を
四辺に置くと、向きはそれぞれ 0°／90°／270°／180° と出て、白い面の見出しは各字の向きに回り、字の「上」側に出た。
書き出した PNG は、逆さの「よい」も横倒しの「あめ」も正位置に起きていて、名前は `よい_1103134509.png` のようになった。

映像の向きも、カメラを横向きに据えた合成映像（上の場面を反時計回りに 90° 倒したもの）で確かめた。0° のままでも横倒しの字として
2語とも読めた。90° に切り替えると、四隅は正立の位置にぴったり移り、2語とも読み直して残った。
180°・270° と回して 0° に戻すと、四隅は元の位置に戻った。

道筋だけ止める処理は、合成映像に白い面が映らないので、まだ効き目を確かめていない（実機で、
残した直後に隣の語が二重に拾われないかを見る）。

**まだ確かめていないこと：** 寝かせたモニタとプロジェクターそれぞれでの閾値、
読めた光の色が部品として拾われないか（「見えているもの」で光が赤くならないこと）。

## やらないと決めたこと

- **OCR の前処理**：回転・二値化・拡大・コントラスト調整。切り出すだけ
- **代わりの読み手**：形の照合（IoU）や学習した分類器で、読めなかったものを読ませること
- **読みのふるい**：仮名だけに絞る・確信度で切る・カタカナをひらがなに寄せる
- **再挑戦**：読めなかった配置を時間をおいて読み直すこと。動かさない限り二度は読まない
- **保存**：残した形は画面にだけ並ぶ。ウィンドウを閉じれば消える
- **方眼・組み立てガイド**
