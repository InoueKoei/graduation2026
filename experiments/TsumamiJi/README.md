# つまみ字 / TsumamiJi

画面の文字の **辺** や **丸まっている部分** をつまんで引っ張ると、そこがゴムのように伸びる。
離すと元の字形にもどる。

親フォルダにある物理版「つまみ字」（MDF ＋ レーザー加工）のデジタル版。
物理版のつまみが一度きりの形状変化しか生まないのに対し、画面上では
引いた量に応じて字形が連続的に変わり、離せば復元する。文字の弾性を反復して確かめられる。

## 動かし方

```bash
npm --prefix experiments/TsumamiJi install
```

```bash
npm --prefix experiments/TsumamiJi run dev
```

> ⚠️ `index.html` を直接開いても動かない。`import opentype from 'opentype.js'` の
> 裸の import が解決できないため、**必ず Vite 開発サーバ経由で開くこと**
> （`works/moji-stack` と同じ制約）。

## 操作

- **輪郭をつまんで引く** — 掴めるのは輪郭の近くだけ。何もない場所を押しても空振りする
- **離す** — 元の字形へもどる
- **左上の入力欄** — 1 文字入れると差し替わる（かな・漢字・欧文）
- **ウェイト** — ゼン丸ゴシックの ボールド / ブラック

調整値はすべて `src/config.js` に日本語コメント付きで置いてある。

### 設計上、つまずいた点

制作中に実際に壊れて直したところ。同じ罠を踏まないための記録。

**1. 凸包と間引きは通さない**

moji-stack の `buildLetterGeometry` は「文字を積む」ための物理形状なので、
輪郭を RDP で間引き、凸包を取って 1 つの塊にしている。ここでそれをやると
「あ」の穴も凹みも消えて、つまむ対象そのものが無くなる。
必要なのは **間引かない、等間隔の、密な輪郭リング**。

**2. 影響範囲は 2D 距離ではなく「輪郭に沿った距離」で測る**

掴んだ点から半径 R 以内、という 2D の測り方だと、「あ」の縦画をつまんだときに
すぐ隣を通る横棒まで巻き込まれ、字の一部がごっそり動く。
＝「つまむ」ではなく「ひきずる」感触になる。
輪郭に沿って（弧長で）測ると、つまんだ線だけが伸び、隣の線は動かない。

ただし弧長だけだとストロークの片側しか動かず輪郭が破れるので、
掴んだ点の **向かい側（同じ線の反対の縁）** も種に加えて両側をまとめて動かす。

**3. 塗りは `nonzero`。`evenodd` ではない**

フォントの輪郭は外周とカウンター（穴）が逆回りなので、`nonzero` でも穴は抜ける。
その上で、引っ張って輪郭が自分自身と重なった部分は `nonzero` なら塗られたままになる。
`evenodd` だとそこが白く抜けて、伸ばした線に破れが入ったように見える。

**4. 距離の設定は px ではなく「字面に対する比」で持つ**

px で固定すると、画面が小さくて字が小さいときに影響半径が字の半分を覆ってしまい、
まったく別の手触りになる。比で持てば、どの画面サイズでも同じ引き心地になる。

**5. 画面サイズは resize イベントに頼らず、毎フレーム見に行く**

タブが隠れている間にウィンドウの大きさが変わると、
隠れている間は `innerWidth` が 0 で、表示に戻ったときには resize イベントがもう来ない。
古い大きさのまま取り残される。毎フレーム比べれば取りこぼさない（`syncSize()`）。
