# 8x2 キャラクタ液晶 — stamps3_lcd0802

ACM0802C-NLW-BBH（青地に白抜き、8文字x2行）を M5Stamp S3A で叩く。
HD44780 互換（ST7066 系）の 4bit モード、読み出しなし。

文字を 5x8 ドットの粒として出す装置なので、[stamps3_kana_dial](../stamps3_kana_dial/) の
電子ペーパーとは逆に、**見えている文字数が 16 文字しかない**ことのほうが効いてくる。

## 部品

- M5Stamp S3A（2.54mm ピンヘッダ版 / S007-PIN254）
- ACM0802C-NLW-BBH
- コントラスト用の抵抗。**半固定は必須ではない**（後述）。まず Vo を GND 直結で試す
- 100Ω 抵抗 1本（液晶基板裏の R7）
- 0Ω 代用の切ったリード線（液晶基板裏の R9）

## 先に液晶の基板裏をやる

付属紙の指示どおり。**R7 と R9 は穴ではなく、四角い銀ランド（チップ抵抗用）**なので、
リード抵抗を使うならリードを 2〜3mm に切って Z 字に曲げ、本体を基板に寝かせてランドに半田付けする。
リードを表（LCD 側）に突き出さないこと。金属フレームに当たる。

| | |
|---|---|
| R7 | 100Ω を 1 本 |
| R8 | 何も付けない |
| R9 | 切ったリード線を渡してブリッジ（0Ω の代用） |
| J1 | 無接続のまま（1番ピン=GND をフレームに落とすためのパッド） |

**余ったリードの輪は必ず切る。** 裸線が隣のランドや配線パターンの上を渡っていると、
押されて接触した時にショートする。ループは電気的に何の役にも立っていない。
団子状になったハンダが隣のランドと繋がっていないかもテスタで当たっておく。

付け終わったら **14 ピンの 1番(GND) と 2番(+5V) に 5V を入れる**。
バックライトがぼんやり光れば R7・R9 とも正解。100Ω なので約 4mA、暗いので暗所で見る。
この 1 回で両方まとめて検証できる。

これをやらないとバックライトが点かない。**白抜きタイプなのでバックライトが点かないと文字は一切見えない。**
配線を疑う前にここを確認する。

### R9 は繋げてよい。R7 は繋げてはいけない

意味が正反対なので取り違えない。

- **R9** は 0Ω の代用。**2 つのランドを繋ぐのが目的**なので、ハンダが渡っても正解の状態。
  電流は数 mA しかないから、リードの長さも太さも関係ない。裸線が立っているのが気になるなら
  固まってから寝かせて、フレームのツメに当たっていないか見るだけでいい
- **R7** は 100Ω。ここをハンダでブリッジすると抵抗が短絡してバックライトに過電流が流れる。
  余ったリードの輪も、隣のランドや配線パターンの上を渡っているなら必ず切る

### 100Ω での明るさは実測する

説明書の `Vlled typ 4.6V / Illed typ 70mA（R=6.8Ω）` は読み方が 2 通りあって、
5V から 100Ω で流れる電流が **4mA 〜 15mA** くらいの幅で変わる。

- LED 単体の Vf が 4.6V と読むなら `(5.0-4.6)/100 = 4mA`
- LED+6.8Ω 全体に 4.6V 印加と読むなら Vf ≒ 4.1V。低電流域では Vf がさらに下がるので 10mA 以上

**確定させるには R7 の両端の電圧を測って `I = V / 100`。** それが実際の電流。
いずれにせよ説明書の基準（R=6.8Ω / 70mA）よりは暗い。安全側に振った指示値なので、そこから始める。
暗すぎたら下げる:

| R7 | ざっくりの電流 |
|---|---|
| 100Ω（指示値） | 4〜15mA |
| 47Ω | その 2 倍強 |
| 22Ω | その 4 倍強 |
| 6.8Ω（説明書の基準） | 約 60〜70mA |

**6.8Ω より下げない。絶対最大 175mA。**

### バックライトはコードを焼く前に光る

バックライトは `Vdd → R7 → LED → R9 → Vss` のただの LED 回路で、
コントローラもファームウェアも関係ない。**5V が来た瞬間に光る**。
だから信号 6 本を繋ぐ前に、電源 2 本（Stamp の `5V`/`G` → LCD の 2番/1番）だけで確かめられる。

- StampS3 に USB-C を挿しただけでは光らない。上の 2 本を繋いである必要がある
- Vo が浮いていても R/W が浮いていても、光ることには関係ない
- 表示エリアは真っ青なまま（文字なし）で正常。見るのはバックライトの光だけ
- 暗いので暗所で見る

## 配線

ACM0802C の 14 ピンは説明書の Pin No. 表のとおり。**1 番が GND。**

| LCD | 記号 | つなぎ先 | なぜ |
|---|---|---|---|
| 1 | Vss | GND | |
| 2 | Vdd | **5V** | 3.3V ではない（後述） |
| 3 | Vo | 半固定の中点 | |
| 4 | RS | G1 | |
| 5 | R/W | **GND に直結** | 保護のため。後述 |
| 6 | E | G5 | |
| 7-10 | DB0-DB3 | 開放 | 4bit モードなので使わない |
| 11 | DB4 | G3 | |
| 12 | DB5 | G7 | |
| 13 | DB6 | G9 | |
| 14 | DB7 | G13 | |
| +/A | BL+ | 配線不要 | R7 経由で 2番(Vdd) から回る |
| -/K | BL- | 配線不要 | R9 経由で 1番(Vss) へ落ちる |

### ヘッダは 2x7。ブレッドボードに直挿しできない

14 ピンは 1 列ではなく **2 列 x 7 行**（奇数列と偶数列）。図面の表記も上が「14 13」、下が「2 1」。
[stamps3_kana_dial](../stamps3_kana_dial/) の電子ペーパー（2x4）と同じで、
ブレッドボードの溝をまたげないので直挿しすると必ずどこかが短絡する。個別の線で引き出す。

### GND は Stamp まで 3 本引かない

1番(Vss) / 3番(Vo) / 5番(R/W) はどれも GND だが、**LCD 側でまとめて 1 本だけ Stamp へ出す**。
帰り線が短くなってノイズに強い。Stamp の GND ピンも 1 本で足りる。
ピン間で渡すときは **2番(Vdd=5V) と 4番(RS) をまたぐ**ので、必ず絶縁された線を使う。

StampS3 側で 2.54mm ピッチのピンヘッダが挿さるのは **G1 / G3 / G5 / G7 / G9 / G13 / G15** と
**G0(BTN) / G43(U0TXD) / G44(U0RXD)**。4bit なので 6 本で足り、**G15 が 1 本余る**（次の入力デバイス用）。
5V は StampS3 のシルク `5V`（USB の VBUS）から取る。

### E に G3 を使わなかった理由

GPIO3 は ESP32-S3 のストラッピングピン。リセット直後はまだ出力になっていないので浮く。
E が浮くとノイズで勝手に書き込みが走りうるので、E は G5 にして、G3 はデータ線（DB4）に回した。
データが化けても E が立たなければ何も起きない。気になるなら E-GND 間に 10kΩ のプルダウンを 1 本。

## Vdd は 5V。3.3V では動かない

ロジック自体は `Vdd-Vss 2.7〜5.5V` なので 3.3V でも動く。それでも 5V にする理由が 2 つある。

1. **バックライト**が Vf≈4.6V。3.3V では点かない。白抜きなので点かない = 何も見えない
2. **コントラスト**に必要な `Vdd - Vo` が 25°C で **4.2〜4.6V**。Vdd=3.3V だと Vo を負電圧にしないと届かない

## ロジックは 3.3V で直結してよい（レベル変換不要）

説明書の `Input voltage (high) Vih = min 2.2V`。0.7xVdd ではなく **2.2V 固定**なので、
Vdd=5V で動かしていても ESP32-S3 の 3.3V 出力で H と認識される。**規格内**なので 74HCT などは要らない。
（Vil は max 0.6V。ESP32 の L は 0V 近辺なので問題ない）

## R/W は必ず GND に落とす

R/W を H にすると LCD 側が DB4-DB7 を **5V で** 駆動する。それが ESP32-S3 の GPIO に入ると壊れる。
だからビジーフラグの読み出しは一切やらず、待ち時間で回す。LiquidCrystal を 6 ピンで作ればその動作になる。

タイミングは余裕がある。説明書の要求は `Enable pulse width 220ns / Enable cycle 500ns / Clear Display 1.64ms`。
LiquidCrystal は E パルスを 1µs、コマンド後に 100µs、clear/home の後に 2000µs 待つので足りている。

## コントラストは Vo を GND 直結から試す

`Vdd - Vo` の推奨は **25°C で typ 4.6V（min 4.2）**、絶対最大 6.5V。
Vdd=5V で **Vo を GND に落とすと Vdd-Vo = 5.0V** で、typ より少し強いが規格内に収まる。
0°C での typ が 4.8V なので、常温〜低温ではむしろちょうどいい。

黄緑の 1602（ポジ型）は Vo を GND に落とすと真っ黒になるが、**これは白抜き（ネガ型）で事情が逆**。
まず GND 直結で試して、それで読めるなら部品は要らない。

濃すぎるとき（背景が濁る／消えているはずの画素がうっすら出る）だけ分圧を入れて Vo を少し持ち上げる:

```
Vdd(5V) --[10kΩ]-- Vo --[1kΩ]-- GND     Vo ≒ 0.45V
```

半固定を使う場合も、**中点（2.5V）では絶対に何も見えない**。GND 側の端から 1 割くらいの狭い窓しかない。
最初の 1 回だけ半固定で最適点を探し、そこの電圧をテスタで測って固定抵抗 2 本に置き換えるのが一番きれい。
半固定は振動で回るので、展示に出すなら固定にする。

## 書き込み

ボードは **ESP32S3 Dev Module**、USB CDC On Boot を Enabled、Flash Size 8MB。
ライブラリは **LiquidCrystal** のみ（Arduino IDE に最初から入っている）。

## まず液晶単体で確かめる

StampS3 に何も繋がずに [test_lcd_only/](test_lcd_only/) を焼く。G0 のボタンでモードが変わる。

| モード | 出るもの | 見るところ |
|---|---|---|
| 0 | 全黒ブロック 16 個 | 半固定を GND 側の端からゆっくり回す。ここが出れば初期化は通っている |
| 1 | 上段 `01234567` / 下段 `ABCDEFGH` | 桁と行の対応。下段が出ないなら 2 行設定が効いていない |
| 2 | CGROM を 0x20 から 8 文字ずつ | **半角カナ（0xA1-0xDF）が入っているか**をここで確かめる |
| 3 | カウンタ | 化けずに回り続けるか |

モード 0 は起動直後にも 1.2 秒出るので、電源を入れてすぐ半固定を合わせられる。

## 本体スケッチ

[stamps3_lcd0802.ino](stamps3_lcd0802.ino) は Serial から送ったバイトをそのまま液晶に出す。
16 文字の窓が右へ流れる。BS/DEL で 1 文字削除、改行で確定（Serial に hex 付きで 1 行出る）、G0 で全消去。

**改行で画面を消してはいけない。** シリアルモニタは行末の `\n` までを一塊で送ってくるので、
`while (Serial.available())` の同じ周回で読み切られ、`render()` が走る前に消える。
打った文字が 1 度も画面に出ない、という症状になる（2026-09-16 に踏んだ）。
確定は Serial に吐くだけにして `pendingClear` を立て、**次の文字が来たときに消す**。

Arduino のシリアルモニタは行単位でしか送れないので、1 文字ずつ窓が流れる様子は原理的に見られない。
見たいときは 9 文字以上を一度に送る。
文字入力側を別に作って、表示だけこれに投げる前提の土台。

液晶に入るのは 1 バイト = 1 文字ぶんなので、**UTF-8 の全角はそのままでは出ない**。
半角カナを出すなら 0xA1-0xDF の生バイトを送る。

## 文字コード — CGROM は A00（2026-09-16 確定）

説明書の CGROM 表で確認した。**JIS X 0201 の半角カナがそのまま入っている。**

| 範囲 | 中身 |
|---|---|
| 0x20-0x7E | ASCII（0x5C は `\` ではなく `¥`、0x7E は `~` ではなく `→`） |
| 0xA1-0xA5 | 。「」、・ |
| 0xA6-0xAF | ヲ ァィゥェォ ャュョ ッ |
| 0xB0-0xB5 | ー アイウエオ |
| 0xB6-0xDD | カ 〜 ン |
| 0xDE 0xDF | ゛ ゜ |
| 0xE0- | ギリシャ文字・記号 |
| 0x00-0x07 | CGRAM（自作の 5x8 を 8 文字まで） |

`lcd.write(0xB1)` で「ア」。

### 濁点が 1 マスを食う

**濁点 0xDE / 半濁点 0xDF は独立した 1 文字**なので、「ガ」は `0xB6 0xDE` の 2 バイト = **画面の 2 マス**。
8 文字しか無い画面で、濁点の有無によって 1 行に入る字数が変わる。
「ガギグゲゴ」は 5 文字だが 10 マスで、1 行に収まらない。
制作でカナを扱うなら、この非対称は設計に効いてくるので先に決めておく。

### ひらがなは出せない

CGROM にひらがなの字形が無い。本体スケッチは Unicode 上でちょうど 0x60 違いなのを使って
**ひらがなをカタカナに寄せて**出している。ひらがなの字形が要るなら CGRAM だが、**8 文字までしか登録できない**。

## つまずきそうなところ

- **真っ暗で何も出ない**: 順に ①バックライトは点いているか ②半固定を GND 側の端からゆっくり
  ③Vdd は本当に 5V か ④R/W は GND に落ちているか
- **上段だけ白いブロックが 8 個、下段は空**: HD44780 の電源投入直後のデフォルト表示。
  つまり **コントラストと電源は合っていて、コマンドが 1 つも届いていない**。疑う順番は
  ①スケッチが焼けているか（Serial に起動メッセージが出るか）
  ②**R/W(5番) が本当に GND に落ちているか** — 浮くと書き込みが一切通らない。最頻出
  ③E と RS の入れ違い ④DB4-DB7 の順違い ⑤GND が Stamp と共通か
- **下段が出ない**: `lcd.begin(8, 2)` の 2 が効いていない。0802 の DDRAM は 上段 0x00-0x07 / 下段 0x40-0x47 で、
  LiquidCrystal の既定値と一致するので、出ないなら配線側
- **文字が出るが時々化ける**: 配線が長い。E の線を短くする、GND を太くする
- **9 文字目が下段に来ない**: 0802 は 8 桁で折り返さない。DDRAM は 1 行 40 桁あるので、
  9 文字目は画面外へ行く。本体スケッチのように自分で `setCursor(0,1)` して 2 分割する
