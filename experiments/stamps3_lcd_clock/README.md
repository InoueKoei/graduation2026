# 8x2 の時計 — stamps3_lcd_clock

M5Stamp S3A + ACM0802C-NLW-BBH。配線・基板裏の処理は [stamps3_lcd0802](../stamps3_lcd0802/) と同じ。

```
09/16ｹﾞﾂ
01:52 ﾊﾚ
```

## 8 マスに入れるための妥協

最初に考えたのは `MM/DD ｹﾞﾂ` だったが、**入らない**。

濁点 `0xDE` が独立した 1 文字なので、曜日のマス数が揃わない:

| | 素直に書くと | マス |
|---|---|---|
| 日 | ﾆﾁ | 2 |
| 月 | ｹﾞﾂ | **3** |
| 火 | ｶﾖｳ | 3 |
| 水 | ｽｲ | 2 |
| 木 | ﾓｸ | 2 |
| 金 | ｷﾝ | 2 |
| 土 | ﾄﾞﾖｳ | **4** |

`MM/DD`(5) + スペース(1) + 土曜(4) = 10 マス。2 マス溢れる。

決めたこと:

- **間のスペースを削る** → 曜日に 3 マス使える
- **曜日は 3 マス右寄せ**。幅が 2 の曜日は左に空白が入るので、日付との間が空いて読める。
  幅が 3 の月曜・土曜だけ詰まって見えるが、これは濁点のぶんなので理屈が通っている
- **火曜は ｶﾖ、土曜は ﾄﾞﾖ に詰める**（ｶﾖｳ / ﾄﾞﾖｳ だと 3-4 マス）
- 天気は 2 マスに収まるものだけ選ぶ。曇りは ｸﾓﾘ(3) ではなく **ｸﾓ**(2)

結果、上段も下段もちょうど 8 マス。

**濁点のある曜日だけ日付に詰め寄る**という見え方は、消そうと思えば消せる（全部 2 マスに揃える）。
残すなら、活字の込め物みたいに「濁点が場所を取る」ことが画面に出ている状態になる。どちらにするかは決めどころ。

## 時刻は ESP32 が持つ

RTC は積んでいない。`millis()` で進めて、PC が 1 分おきに投げ直してずれを潰す。
**PC を抜いても時計は動き続ける**（少しずつずれる）。
未同期のあいだは **コロンが消える**ので、合っていないことが見て分かる。

## Serial のプロトコル（115200、行単位）

| | |
|---|---|
| `S<epoch>` | 時刻合わせ。**ローカル時刻**の秒（PC 側で時差を足しておく） |
| `W<0-4>` | 0=ﾊﾚ 1=ｸﾓ 2=ｱﾒ 3=ﾕｷ 4=ｶﾐ |
| `M<text>` | 上段にメッセージ（UTF-8）。次の `M` か `C` まで出したまま |
| `C` | メッセージを消して日付に戻す |
| `A<n>` | n 回点滅して知らせる |
| `?` | 状態を返す |

メッセージが出ているあいだは **上段だけが日付から入れ替わり、下段の時計は残る**。
時間で自動的に消さないのは、「待ってる」のような消えると困る状態があるため。

`epoch` にローカル時刻を入れて ESP32 側は `gmtime_r()` で読む。
タイムゾーンの設定を一切持たなくて済むので、この方式にしてある。

G0 のボタンで天気が 1 つずつ送る。PC を繋がなくても見た目を確かめられる。

## PC 側

```bash
pip3 install --user pyserial
python3 lcd_daemon.py
```

ポートは自動検出（`/dev/cu.usbmodem*`）。天気は [Open-Meteo](https://open-meteo.com/)（APIキー不要）から
10 分おきに取って、WMO の天気コードを 5 段階に潰している。

```bash
python3 lcd_daemon.py --no-weather        # 時刻だけ
python3 lcd_daemon.py --lat 34.7 --lon 135.5
```

**Arduino IDE のシリアルモニタとは同時に使えない。** ポートは 1 プロセスしか開けないので、
モニタが開いていると待機に入る（閉じれば自動で繋がる）。ESP32 のログはデーモンの `<` 付きの行に出る。

天気の取得に失敗しても時刻の同期は続く。

## 焼き方 — Arduino IDE にコピペしない

```bash
./flash.sh
```

**スケッチブックにコピペしてはいけない。** IDE のスケッチブックにあるコピーは独立したファイルで、
ここのファイルをいくら直しても、焼かれるのは最後にコピペした時点のコードのままになる。

2026-09-16 に丸一晩これを踏んだ。液晶に `commit hex 4D B6 DD ...` と返ってきていたのは、
`M`(0x4D) がコマンドではなく**ただの文字として表示されていた**から。
つまりコマンドを解釈する側のスケッチがそもそも焼かれていなかった。
`stepmatTest` という別名のスケッチに `stamps3_lcd0802` のコードが入ったままだった。

さらに `kana.h` を分けてある以上、`.ino` だけ貼ってもコンパイルが通らない。
IDE を使うなら **File > Open でこのフォルダの `.ino` を直接開く**こと。

`flash.sh` はポートが塞がっていれば止まる（デーモンかシリアルモニタを先に止める）。
`arduino-cli compile` は esptool の `merge-bin` で失敗することがあるが、実体の `.bin` はその前に出来ているので、
スクリプトは `.bin` の有無で成否を判定している。

## 何でも出せる — 送り手は 1 つに絞る

シリアルポートは **1 プロセスしか開けない**（実際に `Resource busy` を踏んだ）。
なので液晶に触れるのは `lcd_daemon.py` だけにして、他は全部 UDP でそこに投げる。

```
Claude Code のフック ─┐
カレンダー監視        ─┼→ udp://127.0.0.1:9123 → lcd_daemon.py → シリアル → 液晶
Slack 受信            ─┘
```

```bash
python3 lcd_send.py "Mオワッタ"    # 上段に出す
python3 lcd_send.py A2             # 2 回点滅
python3 lcd_send.py C              # 消す
```

### なぜ名前付きパイプ（FIFO）ではなく UDP か

FIFO は**読み手がいないと書き込みが永久にブロックする**。
フックから使うとデーモンを起動し忘れた瞬間に Claude Code 自体が固まる。
UDP なら受け手がいなくても捨てられるだけで、絶対に止まらない（実測 33ms で戻る）。

### Claude Code のフック連携

`~/.claude/settings.json` に 3 つ入れてある（2026-09-16）。

| イベント | 上段に出るもの | |
|---|---|---|
| `UserPromptSubmit` | ｶﾝｶﾞｴﾃﾙ | 投げた瞬間 |
| `Notification` | ﾏｯﾃﾙ | 確認待ち。2 回点滅 |
| `Stop` | ｵﾜｯﾀ | 終わった。2 回点滅 |

`async: true` にしてあるので、液晶の都合で Claude の応答が遅くなることはない。
デーモンが動いていなければ何も起きないだけ。

**ｶﾝｶﾞｴﾃﾙ は 7 マス**（ガ が 2 マス）。8 マスにぎりぎり収まっている。
言葉を変えるときは文字数ではなくマス数を数えること。

止めたいときは `~/.claude/settings.json` の `hooks` を消す。元の状態は `settings.json.bak` にある。

## なぜ WiFi + NTP にしなかったか

ESP32-S3 は WiFi を持っているので単体でも組める。それでも PC 連携から始めたのは:

- 展示会場の WiFi は当日まで分からない。認証ページを挟む会場だと詰む
- いま詰めたいのは「8 マスに何をどう収めるか」で、そこは PC 側でいくらでも試せる
- [stamps3_kana_dial](../stamps3_kana_dial/) と同じで、ブラウザから Web Serial で喋れる

単体化するときは、ESP32 側の `handleLine()` の入口を NTP と API に差し替えるだけで、
表示を組む部分（`draw()`）はそのまま使える。
