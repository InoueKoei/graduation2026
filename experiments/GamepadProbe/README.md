# Gamepad Probe — 入力デバイスの実測

ゲームコントローラーやダンスマットが Gamepad API でどう見えるかを実測し、
**そのまま `config.js` に貼れるマッピングを書き出す**ページ。`index.html` 1枚で完結する。

## なぜ作ったか

2つの出来事から。

**1. マッピングは環境ごとに測り直さないといけない。**
`works/DanceToggle/usb-dance-mat-knowledge.md` に書いた `buttons[0..9]` と `axes[1]` は
macOS / Chrome での実測値で、Linux の Chromium が同じ番号を返す保証がない。
Chrome は OS ごとに別の仕組み（macOS は HID、Linux は evdev）でパッドを解釈するため、
**実機に載せるたびに測り直す工程が必ず発生する。** その作業を毎回 DevTools でやるのは高い。

**2. 環境が古いことに気づくのが遅れた。**
Raspberry Pi 3 に Legacy イメージ（Buster）を焼いてしまい、Chromium 74 で DanceToggle が
起動しなかった。原因は `??`（Chrome 80 以降）で、**ES modules は1箇所の構文エラーで全体が黙って止まる**ため、
画面上は何も起きないまま1時間溶けた。「環境が古い」ことを最初に教えてくれる画面が要る。

## 使い方

セキュアコンテキストが必要なので、`file://` ではなくサーバー経由で開く。

```bash
npx --yes http-server experiments/GamepadProbe -p 8990 -c-1
# → http://localhost:8990/
```

1. デバイスを USB で挿す（ドライバ不要）
2. **一度ボタンを押す／マットを踏む。** Chrome は初回入力まで `getGamepads()` を空で返す
3. 「ボタン」「軸」が光れば読めている
4. 「マッピングを記録する」に名前を1行ずつ書いて「記録開始」→ 上から順に踏む
5. 出力された `BUTTON` / `*_AXIS` をコピーして作品の `config.js` に貼る

名前欄の初期値は DanceToggle の11入力（`left` 〜 `center`）。
別の作品で使うときは書き換える。

## 設計上の判断

**ES2019 以下の構文だけで書いている。**
`??` や `?.` を使うと Chromium 79 以下で構文エラーになり、
**「このブラウザは古い」という結論そのものが表示できなくなる。** 診断ツールが診断対象に殺されては意味がない。
`??` が使えるかどうかは `new Function('return 1 ?? 2')` を try/catch で包んで検出している。

**単一ファイルにしている。**
他の作品は `index.html` + `script.js` + `config.js` に分けているが、これは診断用なので
`scp` 1回で知らない機械に持ち込めることを優先した。

**軸も記録対象にしている。**
ダンスマットの中央パネルはボタンではなく `axes[1]` に出る。
ボタンだけを拾う実装だと中央が永久に記録できない。
記録開始時の軸の値を基準に取り、そこから 0.5 以上動いたら軸入力とみなす。

**一度離すまで次に進まない。**
押しっぱなしだと1回の入力で複数の項目が埋まってしまう。
入力が無い状態を1フレーム挟んで初めて次を受け付ける。

## 既知の制約

- **セキュアコンテキスト必須。** `http://192.168.x.x` のような LAN 越しの平文 HTTP では
  `getGamepads()` が常に空を返す。`localhost` か HTTPS で開くこと
- 同一製品を2台挿すと `id` で区別できない。`index`（USB の列挙順）でしか分けられないので、
  物理的にどちらがどちらかはラベルを貼って管理する
- ブラウザがフォーカスを失うと入力が届かなくなる
