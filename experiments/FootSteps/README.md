# FootSteps — 歩いた軌跡を線にする

両足に付けた IMU から歩行を記録し、上から見た足跡トラックとして可視化する装置。
最終的には「ステップの軌跡を線としてカナにする」「場所や踏みを記号化して母音とする」という
2つのモードに向かうが、**それらは別モードで、まずは軌跡が線として出るところ（MVP）だけを作る**。

## 構成

```
[左足] StampS3A + MPU6050(実体は MPU6500 系クローン)    → foot_left/
[右足] CoreS3 + 内蔵 BMI270                             → foot_right/
共有   ZUPT・姿勢・変位の推定                            → common/foot_core.h
```

推定のコードは左右で完全に同一（`foot_core.h`）。違うのはセンサの読み方だけで、
CoreS3 は `M5.Imu`、StampS3A は `common/mpu6500.h`（後述の理由で自前）。

## なぜ加速度のピークで歩数を数えないか

最初にあった `foot_sync_monitor.py`（Qwen 生成）は `az`（センサZ軸の加速度）を「上下動」として
扱っていたが、これは歩行計測として成立しない。

- **足は1歩で 70〜90 度ピッチ回転する。** `az` の振れの主成分は重力ベクトルがセンサZ軸に
  射影される角度の変化であって、踏んだ強さではない。取り付け角が少し違うだけで別物を測ることになる
- 素の MPU6050 ライブラリのデフォルトは ±2g / ±250dps。足装着では踵接地 3〜6g、
  遊脚期のピッチ角速度 400〜600dps に達するので**常時クリップしていた**
- 時刻が PC の到着時刻しかなく、WiFi ジッタ（10〜50ms）が歩行イベントの精度と同じオーダーだった

代わりに、**「足が床に静止している区間（立脚期）」を検出して、そこで速度がゼロであることを
拘束条件に使う**（ZUPT）。判定に使うのは `‖a‖` と `‖ω‖` という向きに依存しないスカラー量だけなので、
取り付け角のズレと左右のハード差が判定式に入ってこない。

## つまずいた点

### 1. 「MPU6050」が MPU6050 ではなかった

M5Unified は `cfg.external_imu = true` で Grove 上の外部 IMU を拾ってくれる。
`Ex_I2C` も StampS3 のボードテーブルに SDA=G13 / SCL=G15 で登録済みで、配線さえ合えば設定不要のはずだった。

ところが `M5.Imu` が `none` のまま。バスには 0x68 で応答があるのに拾われない。

`WHO_AM_I`（レジスタ 0x75）を直接読んだら **0x70**。これは MPU-6500 系の ID で、
`MPU6886_Class::begin()` は `0x19`(MPU6886) / `0x68`(MPU6050) / `0x71`(MPU9250) しか受け付けないため、
**中身は正常に動くのに ID だけで弾かれていた**。「MPU6050」として売られているクローンによくある値。

ライブラリを書き換えると更新で消えるうえ他のスケッチにも影響するので、
`common/mpu6500.h` に最小のドライバを書いた（約80行）。レンジは M5Unified が CoreS3 に設定するのと
同じ **±8g / ±2000dps** に揃えてある。単位を合わせるだけで、それ以上の左右較正はしない。

### 2. USB CDC が詰まってサンプリングごと止まる

ESP32-S3 のネイティブ USB CDC は、**受信側が誰も繋がっていないと送信バッファが詰まって
`Serial.printf` がブロックする**。実測で 12 秒に pose が 5 行しか出ず、デバイス時刻だけ 39 秒進んでいた。

`Serial.setTxTimeoutMs(0)` で、読み手がいないぶんは捨てて先へ進むようにする。

さらに悪いことに、この状態だと**書き込み自体も通らなくなる**（`Failed to connect to ESP32-S3:
No serial data received`）。復帰させるには esptool のリセット方式を変える。

```bash
~/Library/Arduino15/packages/esp32/tools/esptool_py/5.3.0/esptool \
  --chip esp32s3 --port /dev/cu.usbmodem101 --before usb-reset chip-id
```

これで一度掴めば、以降は通常の `arduino-cli upload` が通る。USB を挿し直しても直る。

なお、シリアルを読むスクリプト側で DTR/RTS を叩いてリセットをかけるのは**やめたほうがいい**。
ハードウェア USB-JTAG ではチップが応答しない状態に落ちることがある。

### 3. 画面の再描画が 200Hz を壊す

サンプリングと描画を同じループでやると、全面再描画がループを食って**実測 140Hz** まで落ちた。
推定は等間隔サンプリングが前提なので、これはそのまま精度の劣化になる。

サンプリングを FreeRTOS タスクにして **core 0 に固定**し、描画とシリアル出力を core 1 に分けた。
接地イベントはキュー経由で渡す。これで **200.0Hz** ちょうどが出る。
（Stage 2 で SoftAP + WebSocket を足すときも、この分離がそのまま効く。）

## 検証状況

2026-08-30 時点。**机の上に静止させた状態まで**確認済み。

| | 右足 CoreS3 (BMI270) | 左足 StampS3A (0x70) |
|---|---|---|
| サンプリング | 200.0 Hz | 200.0 Hz |
| pose 出力 | 24.7 Hz | 23.3 Hz |
| 静止中の誤検出 | 0 歩 | 0 歩 |
| 静止中のドリフト | x=0.000 y=0.000 | x=0.000 y=0.000 |

**まだ確認していないこと**（実際に足に付けて歩く必要がある）:

1. **立脚検出**：手に持って「踏む→浮かす」を 10 回 → イベントが 10 回ちょうど出るか。
   靴に付けて 20 歩 → 歩数が合うか
2. **変位**：1m を 4 歩で歩いて `Σdx` が 1m 前後になるか。誤差 10% 以内なら実用
3. **ヨードリフト**：原点で構え → 直進 10 歩 → 振り返って戻る → 始点に戻るか。
   30 秒でのドリフト量が、**1本の線に許される長さの上限**を決める
4. **四角と丸を歩いて、線が四角と丸に見えるか** ← MVP の合否はここ

## 使い方

```bash
# 右足（CoreS3）
arduino-cli compile -b esp32:esp32:m5stack_cores3 foot_right
arduino-cli upload  -b esp32:esp32:m5stack_cores3 -p /dev/cu.usbmodem101 foot_right

# 左足（StampS3A）
arduino-cli compile -b esp32:esp32:m5stack_stamp_s3 foot_left
arduino-cli upload  -b esp32:esp32:m5stack_stamp_s3 -p /dev/cu.usbmodem1101 foot_left
```

`common/` のヘッダは各スケッチフォルダにシンボリックリンクで置いてある
（Arduino はスケッチフォルダの外を include できないため）。

- 右足：画面をタッチすると「構え」＝位置とヨーの原点リセット
- 左足：G0 のボタンで同じ。内蔵 RGB LED(G21) が 緑=立脚 / 橙=遊脚 / 赤点滅=IMU 見つからず / 白=リセット直後

### 配線（StampS3A ↔ MPU6050）

| MPU6050 | StampS3A |
|---|---|
| VCC | 5V |
| GND | GND |
| SDA | G13（Grove） |
| SCL | G15（Grove） |
| AD0 | GND（アドレス 0x68） |

## 出力フォーマット

接地イベント（1歩ごと）:

```json
{"t":"step","foot":"L","seq":142,"t_us":9481233,"dx":0.62,"dy":-0.04,"dz":0.01,
 "x":2.41,"y":0.13,"yaw":0.31,"pitch_hs":-0.21,"stance_ms":610,"swing_ms":390,
 "peak_a":4.2,"peak_w":510}
```

ライブ姿勢（25Hz）:

```json
{"t":"pose","foot":"L","t_us":9481500,"pitch":-0.2,"roll":0.02,"yaw":0.31,
 "state":"swing","x":2.41,"y":0.13,"hz":200.0}
```

MVP が使うのは `dx, dy, yaw` だけ。`stance_ms / peak_a / pitch_hs` は線を描くのに要らないが、
後のモードB（踏み→母音）がこの数値から作られるので、いま一緒に吐いてある
（あとからファームを焼き直さずに済む）。

### データ源は4つあり、差し替えられる

無線（Stage 2）ができる前でも検証できるように、**Web Serial で USB から直接読める**ようにしてある。

| | 用途 |
|---|---|
| **USB を追加** | Web Serial。押すたびポートを1つ足す。**両足なら2回押す**。Chrome / Edge 限定 |
| **WebSocket** | Stage 2 用。CoreS3 の SoftAP に繋いでから `ws://192.168.4.1/ws` |
| **デモ** | 実機なしで四角と丸を歩いたことにする。押すたび四角↔丸が入れ替わる |
| **ファイル再生** | 書き出した JSON、またはシリアルのログを貼った JSON Lines を時刻どおりに再生 |

### 描くもの

- **線** — 左右の接地点の中点を繋いだポリライン。これが MVP の主役。
  片足しか繋がっていないときは、その足の接地点をそのまま繋ぐ（USB 1本での検証用）
- 接地点ごとの足形グリフ（ヨーで回す。青=左足 / 赤=右足）
- 動いている足のライブ位置（塗り=立脚 / 抜き=遊脚）
- 1m 方眼、原点（構えの位置）、スケールバー

**足形の色や濃さで踏みを表す演出は入れていない。** それはモードBの領分で、
先に混ぜると「線が正しく出ているか」を確かめにくくなる。

ドラッグでパン、ホイールでズーム。触ると自動フィットが外れるので、戻すときは「全体を表示」。

### 有線で両足を出す手順

1. 2台とも USB で Mac に繋ぐ
2. ビューアで「USB を追加」を**2回**押し、`usbmodem101`（CoreS3）と `usbmodem1101`（StampS3A）をそれぞれ選ぶ
3. 両足を揃えて立ち、「**構え（原点リセット）**」を押す
4. 歩く

**「左足用」「右足用」とボタンを分けていない。** 足の識別はデータ側が持っていて
（どのイベントにも `"foot":"L"/"R"` が入っている）、ポートを選ぶ順番は結果に影響しない。
分けると押し間違えたときに表示と実体がずれるので、あえてまとめてある。

### 「構え」は装置にも届く

ビューアの「構え」は、繋がっている全ポートへ `{"cmd":"origin"}` を1行で送る。
ファーム側は `pollCommand()` がこれを拾って原点を打ち直し、`{"t":"origin","foot":"..."}` を返す。

足に装着した状態では CoreS3 の画面も StampS3A の G0 ボタンも押せないので、この経路がないと
両足の原点を揃えられない。**左右のヨー原点と位置原点が揃うのはこの瞬間だけ**なので、
1本の線を引くたびにここへ戻る。

### 左右の間隔は測っていない（構えの仮定で補っている）

各足は**自分の原点 (0,0) から**推測航法する。つまり装置の出力には、
左右の足が物理的にどれだけ離れているかも、踏み出しの前後差も入っていない。両足とも (0,0) から始まる。

そのままだと構えた瞬間に左右が同じ点に重なるので、ビューア側で `FOOT_OFFSET = 0.10`（片側 10cm）を
足している（`js/track.js`）。ヨー原点を揃えた直後は進行方向が +x なので、左足が +y 側。

これは**測定値ではなく仮定**。左右の実際の間隔を測る手段はこの構成にはない。
線そのものは左右の中点なので、対称なオフセットでは影響を受けない。

### 動作確認（2026-08-30）

- デモの四角（一辺 3m）で 19 歩 → **線が四角として描かれることを確認**。
  SVG は 3260×3260mm、CSV は 13 列。コンソールエラーなし
- **実機の JSON を Web Serial と同じ経路（`LineBuffer` → `parseLine`）に通して確認。**
  行の途中で切れる分割も復元でき、左右のオフセット（+0.100 / −0.100）が正しく適用される
- **シリアル経由の「構え」を実機2台で確認。** 両方が `{"t":"origin","foot":"..."}` を返す
- **40秒静止で両足とも誤検出0歩・ドリフト0。** pose は 24Hz、サンプリングは 200.0Hz

**動かした状態ではまだ確認していない。** 次に歩いたときが初めての本番になる。

デモは実機の出力を忠実に模してある（足ごとに自分の原点から始まる）ので、
デモで見えている絵と実機の絵は同じ規則で描かれる。
