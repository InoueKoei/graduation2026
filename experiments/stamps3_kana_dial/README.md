# つまみ字盤 — stamps3_kana_dial

つまみを回してかなを選び、押して確定する文字入力機。
[TsumamiJi](../TsumamiJi/) が画面の中のつまみだったのに対して、こちらは手で回すつまみと紙のような画面でやる版。

回すと文字盤が動き、選ばれた 1 文字が 16px のビットマップを 11 倍に拡大したドットとして出る。
にじまない代わりに角が立つ見え方で、電子ペーパーの粒立ちとそろえてある。

## 操作

| 操作 | 結果 |
|---|---|
| 回す | 1 文字ずつ送る |
| 押しながら回す | 行送り（あ行 → か行 …） |
| 短く押す | 確定（画面下の帯に 1 文字追加、Serial にも出力） |
| 0.7 秒押す | 1 文字消す（LED 赤） |
| 2.5 秒押す | 全消去 + 全画面リフレッシュ（LED 橙、残像取り） |

確定するたび現在の文字列が 115200bps の Serial に 1 行出る。ブラウザ側の作品に Web Serial で流し込める。

## 部品

- M5Stamp S3 (V0.3)
- WeAct Studio 4.2" Epaper Module 400x300（I/O は 3.3V）
- ロータリーエンコーダモジュール（GND / S1 / S2 / KEY / 5V の 5 ピン基板、EC11）

## 配線

StampS3 で 2.54mm ピッチのピンヘッダが挿さるのは **G1 / G3 / G5 / G7 / G9 / G13 / G15** と
**G0(BTN) / G43(U0TXD) / G44(U0RXD)**。EN はチップのリセット端子なので GPIO には使えない。
必要なのがちょうど 9 本なので、G0 だけ予備に残してある。

電子ペーパーは基板シルクの 1→8 の順が BUSY / RES / D/C / CS / SCL / SDA / GND / VCC。

| e-paper | StampS3 | なぜそこか |
|---|---|---|
| BUSY | G44 | U0RXD。起動時から入力なので BUSY 向き |
| RES | G43 | U0TXD。起動時に ROM ログが出るが、`init()` でリセットし直すので影響しない |
| D/C | G7 | |
| CS | G9 | |
| SCL | G13 | Grove の SDA ピンだが I2C は使っていない |
| SDA | G15 | Grove の SCL ピン |
| GND | GND | |
| VCC | 3V3 | I/O は 3.3V |

| エンコーダ | StampS3 |
|---|---|
| S1 | G1 |
| S2 | G3 |
| KEY | G5 |
| GND | GND |
| 5V | 3V3（3.3V で動く） |

### パネル側の 2x4 ピンはブレッドボードに直挿しできない

モジュールの 8 穴は 2 列 x 4 列で、上下の間隔が 2.54mm しかない。
ブレッドボードは横 5 穴が 1 つの島で、溝の幅は 0.3 インチ（7.62mm）あるため、
DIP の IC のように溝をまたげない。挿すと必ずどこかが短絡する。

- 4 本の並びを行方向にして挿す → 上下のペアが同じ島に落ちて **7:GND と 8:VCC が直結**
- 90 度回して挿す → 上段の GND/SCL/D_C/BUSY が全部つながり、下段の VCC/SDA/CS/RES も全部つながる

逃がし方:

1. 2x4 のピンヘッダを立てて、オス-メスのジャンパ 8 本で 1 本ずつ別の行へ（いちばん手軽）
2. 8 ピンの FFC コネクタ側を使う。2x4 と同じ 8 信号が出ているので、
   FFC→2.54mm の変換基板を噛ませれば 1x8 の一列になり直挿しできる
3. ユニバーサル基板に 2x4 のメスヘッダを載せ、裏で 1x8 に引き直した変換基板を自作する

StampS3 側も使うのは奇数列（G1/G3/G5/G7/G9/G13/G15）が一列に並んでいるので、
パネル側を 1x8 にできると配線が素直になる。

Serial は USB-CDC なので、G43 / G44 を GPIO に使ってもログは USB 側に出る。
逆に **G43 を入力（エンコーダ側）に使ってはいけない**。起動時の ROM ログの出力と、
接点が閉じているときの GND とがぶつかる。

G0 は BTN 兼ストラッピングピン。ここにエンコーダの KEY を繋ぐと、
つまみを押したまま電源を入れたときにダウンロードモードで起動するので避けている。

## 書き込み

Arduino IDE で、ライブラリマネージャから 3 つ入れる。

- GxEPD2
- Adafruit GFX Library
- U8g2_for_Adafruit_GFX

ボードは **ESP32S3 Dev Module**、USB CDC On Boot を Enabled、Flash Size 8MB。

## まず電子ペーパー単体で確かめる

エンコーダを繋ぐ前に [test_epd_only/](test_epd_only/) を焼くと、パネルだけを切り分けられる。
配線はそのままでよい（エンコーダは挿さっていなくていい）。

枠・原点・1px 市松・線幅 1〜4px・書体見本を全面書き換えで一度描き、
以後 5 秒おきに画面下の枠だけを部分更新して、かかった ms を Serial に出す。

実測（GDEY042T81 / SSD1683、2026-08-26 に確認）:

| | BUSY が立っている時間 | 呼び出し全体 |
|---|---|---|
| 部分更新（368x56 の枠） | 563 ms | 655 ms |
| 全面書き換え | 2.20 s | 2.50 s |

見るところ:

- 起動直後の `BUSY before init` が常に 0 のままなら、たいてい配線違いか VCC が来ていない
- `fast partial update : yes` なら SSD1683 版。`no` なら冒頭の `PANEL_SSD1683` を 0 にする
- 部分更新が全面と同じくらいの ms しかかからないなら、部分更新が効いていない
- 下の枠だけがきれいに書き換わり、上のテストページが崩れなければ合格

## つまずきそうなところ

- **画面が真っ白／文字化けする**: WeAct の 4.2" はロットでコントローラが違う。スケッチ冒頭のパネル指定を
  `GxEPD2_420_GDEY042T81`（SSD1683、部分更新が速い）から `GxEPD2_420`（GDEW042T2 / UC8176）に差し替える。
  後者は部分更新が遅いので、スケッチ側は `hasFastPartialUpdate` を見て自動で全面書き換えに落とす。
- **回す向きが逆**: `ENC_REVERSE` を 1 にする。
- **1 クリックで 2 文字進む**: `ENC_COUNTS_PER_DETENT` を 2 にする（半クリック型のエンコーダ）。
- **書き換えが追いつかない**: 手が止まって 160ms 経ってから 1 回だけ描いている。`lastInputMs` の閾値で調整。
- **flash が足りない**: 日本語フォントを `FONT_JP` の定義で `u8g2_font_unifont_t_japanese1` に落とす。
  ただしヘッダの「字」「盤」が出なくなる可能性がある。
